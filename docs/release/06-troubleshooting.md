# 06. Эксплуатационная диагностика

Статус документа: черновик 0.1. Только реально реализованные режимы отказа и сообщения;
поведение, которого нет в коде, не обещается.

## 0. Общие принципы

- Человеческие сообщения CLI и журнала — русские; строки сетевого протокола — английские и
  не переводятся `[ИСТОЧНИК src/main/java/ru/octomem/cli/Main.java:63, docs/04:240]`.
- CLI не печатает значения конфигурации, пути, причины I/O-исключений и stack trace
  `[ИСТОЧНИК design/config-schema.md:83]`.
- В журнале нет ключей и значений кеша, а `CAPACITY` ограничивается по частоте
  (не чаще раза в секунду) `[ИСТОЧНИК src/main/java/ru/octomem/stats/SafeLogger.java:14,69-88]`.
- Ошибки протокола имеют фиксированные строки `[ИСТОЧНИК docs/04:228-242]`.

## 2. Ошибки конфигурации (код 2)

Возможные сообщения `[ИСТОЧНИК src/main/java/ru/octomem/config/ConfigLoader.java:64,85,94,98,108,114,120,132,137,142,157,257, design/config-schema.md:65-79]`:

- `Ошибка аргументов. Используйте --help; каждый параметр задаётся только один раз.`
- `Ошибка конфигурации <известный ключ>: <причина без значения>.`
- `Неизвестный ключ конфигурации, строка <номер>. См. --help.`
- `Повтор ключа <ключ>, строка <номер>.`
- `Неверный формат строки конфигурации: <номер>. Ожидается ключ=значение.`
- `Не удалось прочитать файл конфигурации. Проверьте путь, права доступа и кодировку UTF-8.`
- `Файл конфигурации превышает допустимый объём.`

Диагностика: запустить только проверку —
`java -jar octomem-1.0.0.jar --check-config --config <файл>`; она не открывает порт и не
создаёт потоков `[ИСТОЧНИК Main.java:140-143, design/config-schema.md:18]`.
Типичные причины по границам из документа 02 §5: неизвестный/повторяющийся ключ,
`item.maxSize > memory.limit`, `protocol.maxChunkBytes < 2`, `connections.pendingWriteBytes < 2`,
порт вне `1..65535`, небуквальный `listen.address`, значение `eviction.policy ≠ lru`,
недопустимый `log.level` `[ИСТОЧНИК ConfigLoader.java:162-254]`.

## 3. Ошибка запуска (код 1)

- Сообщение журнала: `Ошибка запуска или работы сервера.` (`START_FAILURE`, уровень error)
  `[ИСТОЧНИК SafeLogger.java:20]`.
- Причина не выводится в текст (безопасность), поэтому диагностировать нужно по
  окружению: занятость порта, доступность адреса, права. `[РЕКОМЕНДАЦИЯ]`
- Проверка конфигурации (`--check-config`) **не** проверяет занятость порта и доступность
  адреса — это явно указано `[ИСТОЧНИК design/config-schema.md:18]`.
- Если порт занят, смените `listen.port` и перезапустите.

## 4. Привязка и доступность

- По умолчанию сервер слушает только `127.0.0.1`
  `[ИСТОЧНИК src/main/java/ru/octomem/config/ConfigLoader.java:24-25]`.
- Привязка к не-петлевому адресу логирует предупреждение `BROAD_BIND`
  `[ИСТОЧНИК src/main/java/ru/octomem/cli/CacheServer.java:124, SafeLogger.java:18]`.
- Встроенной аутентификации нет; из недоверенной сети доступ открыт
  `[ИСТОЧНИК docs/07-security-operations-release.md:11,33-35]`.

## 5. Нехватка памяти (`out of memory storing object`)

- Ответ выдаётся после попытки вытеснения, когда память так и не выделена
  `[ИСТОЧНИК DefaultCacheEngine.java:303-318, CacheCommandDispatcher.java:195]`.
- Диагностика: `stats` — `evictions`, `bytes`, `limit_maxbytes`; `stats slabs` —
  `used_chunks`, `total_pages`, `mem_requested`
  `[ИСТОЧНИК CacheCommandDispatcher.java:239-315]`.
- Возможная причина OOM при свободном логическом бюджете — фрагментация по классам
  размеров: классы начинаются с 64 байт и растут с шагом 1,25
  `[ИСТОЧНИК FfmSlabAllocator.java:42-48,97-100]` `[РЕКОМЕНДАЦИЯ]`.
- Изменение `memory.limit` требует перезапуска; онлайн-изменения бюджета нет
  `[ИСТОЧНИК docs/07-security-operations-release.md:80]`.

## 6. Слишком большая запись (`object too large for cache`)

- Предел применяется к **полной** записи (ключ + служебные поля + значение + выравнивание)
  `[ИСТОЧНИК docs/04:21, DefaultCacheEngine.java:300-301]`.
- Увеличение `item.maxSize` ограничено сверху `memory.limit`
  `[ИСТОЧНИК ConfigLoader.java:73-75]`.

## 7. `stats items`/`stats slabs` недоступны

- Ответ `SERVER_ERROR statistics unavailable`, если снимок классов не помещается в бюджет
  `[ИСТОЧНИК CacheCommandDispatcher.java:169-176, AtomicStatsRegistry.java:227-244]`.
- Бюджет снимка классов — `min(memory.limit / 16, 16 МиБ)`
  `[ИСТОЧНИК DefaultCacheEngine.java:131]`.
- Общий `stats` при этом продолжает работать `[ИСТОЧНИК CacheCommandDispatcher.java:159-163]`.

## 8. Пустой кеш после перезапуска

- Это ожидаемое поведение, а не дефект: данные не персистентны
  `[ИСТОЧНИК docs/01-product-brief.md:13, NG1]`.
- Следствие: `curr_items = 0`, рост `get_misses`; приложение прогревает кеш
  `[ИСТОЧНИК docs/07-security-operations-release.md:119-121]`.

## 9. Просроченные записи и задержка очистки

- Просроченная запись не отдаётся, но может освободиться не мгновенно: удаление ленивое
  при обращении плюс фоновая очистка с периодом `expiry.reclaimIntervalSeconds`
  (по умолчанию 1 с), не более 256 записей за проход
  `[ИСТОЧНИК DefaultCacheEngine.java:143-148,190-198,695-714]`.

## 10. Медленные клиенты и глубокий конвейер

- `connections.pendingWriteBytes` ограничивает подготовленные, но не записанные байты;
  при достижении лимита транспорт приостанавливает выборку частей (backpressure)
  `[ИСТОЧНИК docs/03-architecture-specification.md:330]`.
- `connections.maxInflightCommands` ограничивает декодированные, но не завершённые команды;
  при достижении предела чтение из сокета останавливается
  `[ИСТОЧНИК docs/03-architecture-specification.md:331]`.
- `connections.idleTimeoutSeconds = 0` по умолчанию **не** закрывает простаивающее
  соединение; задайте положительное значение, чтобы ограничить удержание
  `[ИСТОЧНИК docs/03-architecture-specification.md:332, ConfigLoader.java:36]`.

## 11. Что диагностикой не покрывается (реализации нет)

Следующие средства отсутствуют и не должны предполагаться `[НЕ ПРОВЕРЕНО]`:

- HTTP health-эндпойнт — P2, в 1.0 нет `[ИСТОЧНИК docs/02-general-technical-specification.md:118]`;
- `stats conns`/`stats sizes`/`stats cachedump` — P2 `[ИСТОЧНИК docs/04:204]`;
- административная команда `shutdown` — не планируется `[ИСТОЧНИК docs/04:264]`;
- онлайн-изменение `memory.limit` — только перезапуск `[ИСТОЧНИК docs/07:80]`;
- вывод отклонённых соединений в `stats` — «not yet exposed through protocol stats»
  `[ИСТОЧНИК src/main/java/ru/octomem/transport/NioTransport.java:189-193]`;
- автоматический прогрев кеша — нет; прогрев выполняет приложение
  `[ИСТОЧНИК docs/07:119-121]`.
