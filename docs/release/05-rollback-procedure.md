# 05. Процедура отката

Статус документа: черновик 0.1. Процедура описывает возврат предыдущего артефакта.

## 1. Когда применять

Откат применяется, если после обновления (документ 04) наблюдается регрессия:
сервер не запускается (код 1), конфигурация отвергается (код 2), поведение протокола или
наблюдаемые показатели заметно отличаются от предыдущей версии, либо пилотный сценарий
не проходит.

## 2. Ключевое честное утверждение

> **Содержимое кеша не сохраняется между запусками и не восстанавливается откатом.**

`octomem` хранит данные только в оперативной памяти и не пишет их на диск
`[ИСТОЧНИК docs/01-product-brief.md:13, NG1; docs/03-architecture-specification.md:341-344]`.
Резервное копирование содержимого кеша не выполняется
`[ИСТОЧНИК docs/07-security-operations-release.md:119-121]`.
Откат меняет **только исполняемый артефакт**; он не возвращает ни одну запись кеша.
Фактически содержимое уже потеряно при первой же остановке/перезапуске в ходе обновления,
поэтому откат не может «вернуть данные назад».

## 3. Точные последствия для семантики кеша

После остановки и запуска (любого — вперёд или назад):

- **Все ключи отсутствуют.** `curr_items` начинается с 0; первые обращения дают промахи
  (`get_misses` растёт), кеш считается «холодным». Приложение обязано переживать это как
  обычный промах `[ИСТОЧНИК docs/01-product-brief.md:13]`.
- **Токены `cas` не сохраняются.** Счётчик версий инициализируется в новом процессе
  `[ИСТОЧНИК src/main/java/ru/octomem/engine/DefaultCacheEngine.java:122]`. Условное
  обновление по `cas`-токену, полученному до перезапуска, не сработает как ожидалось:
  клиент получит `EXISTS` (несовпадение версии) либо `NOT_FOUND` (ключа нет)
  `[ИСТОЧНИК docs/04-protocol-compatibility-specification.md:97]`.
- **TTL-состояние не сохраняется.** Ни относительные, ни абсолютные сроки не переносятся:
  каждая запись должна быть создана заново.
- **Состояние `flush_all` не сохраняется.** Инвалидация относится к прежнему процессу
  `[ИСТОЧНИК docs/04-protocol-compatibility-specification.md:169]`.
- **Счётчики `stats` сбрасываются**, `uptime` начинается заново
  `[ИСТОЧНИК docs/03-architecture-specification.md:9]`.
- **`evictions`/`reclaimed` начинаются с нуля**, поэтому сравнение «до/после» по этим
  полям требует отдельного базового отсчёта.
- **Всплеск нагрузки на источник истины.** При холодном старте приложение лавинообразно
  обращается к основной базе; эксплуатации следует документировать прогрев
  `[ИСТОЧНИК docs/07-security-operations-release.md:119-121]` `[РЕКОМЕНДАЦИЯ]`.

## 4. Порядок отката

`[РЕКОМЕНДАЦИЯ]` Проверяемые шаги, не заявляющие восстановление данных.

1. **Остановить сервер штатно** (SIGINT/SIGTERM); дождаться `STOPPED`
   `[ИСТОЧНИК CacheServer.java:197]`.
2. **Восстановить предыдущий JAR** из сохранённой копии (шаг 1 документа 04) на место
   текущего либо указать его отдельным путём в команде запуска.
3. **Проверить целостность артефакта:** сравнить SHA-256 восстановленного JAR со
   сохранённым при обновлении `[РЕКОМЕНДАЦИЯ]`.
4. **Проверить версию и конфигурацию без запуска:**
   `java -jar <прежний>.jar --version`; ожидается строка версии предыдущего артефакта
   `[ИСТОЧНИК Main.java:130-132]`, и
   `java -jar <прежний>.jar --check-config --config <файл>`
   `[ИСТОЧНИК Main.java:140-143]`.
5. **Запустить сервер** и проверить `version` по протоколу
   `[ИСТОЧНИК CacheCommandDispatcher.java:157]`.
6. **Снять `stats`** и убедиться, что набор полей полон и счётчики начались с нуля
   (это ожидаемо, а не дефект) `[ИСТОЧНИК CacheCommandDispatcher.java:159-163]`.
7. **Выполнить пилотный сценарий** и сравнить поведение с прежней версией
   `[ИСТОЧНИК docs/04-protocol-compatibility-specification.md:294-302]`.

## 5. Проверка данных

Понятия «проверка сохранности данных кеша» при откате не существует, поскольку данные не
персистентны. Проверяется корректность **поведения** восстановленного артефакта:

- сервер запускается и принимает соединения;
- `version` возвращает ожидаемую строку;
- `stats` отвечает;
- приложение снова наполняет кеш и наблюдает ожидаемые попадания;
- ключевые прикладные сценарии проходят без правок логики приложения
  (цель NFR-20 `[ИСТОЧНИК docs/04-protocol-compatibility-specification.md:302]`).

## 6. Ограничения

- `[НЕ ПРОВЕРЕНО]` Восстановление содержимого кеша невозможно — постоянного хранения нет.
- `[НЕ ПРОВЕРЕНО]` Процедура отката на чистом стенде не выполнялась в рамках этого
  документа.
- `[НЕ ПРОВЕРЕНО]` Откат конфигурации: если новая версия изменила трактовку ключей или
  значений по умолчанию (для major-версии это допустимо
  `[ИСТОЧНИК docs/07-security-operations-release.md:109]`), вместе с JAR следует
  восстановить и согласованный файл конфигурации.
