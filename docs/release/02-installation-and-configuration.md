# 02. Установка и настройка

Статус документа: черновик 0.1. Все флаги и ключи сверены с исходным кодом.

## 1. Требования

- **OpenJDK 25** (обязательно). Байткод 25 не запускается на JDK 21
  `[ИСТОЧНИК docs/java-platform.md:9, pom.xml:30]`.
- Запуск из каталога, содержащего `octomem-1.0.0.jar`; административные права не
  требуются, сетевые исходящие соединения не нужны
  `[ИСТОЧНИК docs/07-security-operations-release.md:56]`.
- Открытый для приёма TCP-порт по настройке (по умолчанию `11211` на `127.0.0.1`).
- Аутентификации и шифрования канала нет; сервер предназначен для доверенного сегмента
  `[ИСТОЧНИК docs/07-security-operations-release.md:11]`.

## 2. Установка

Установка — распаковка/размещение JAR в доступном пользователю каталоге. Онлайн-активация
и обязательные внешние сервисы отсутствуют `[ИСТОЧНИК docs/07-security-operations-release.md:56]`.

`[НЕ ПРОВЕРЕНО]` Скрипты запуска и файл конфигурации по умолчанию в репозитории
отсутствуют (см. документ 01 §5); запуск выполняется непосредственно `java -jar`.

## 3. Фактические команды командной строки

Разбор аргументов реализован в `Main.runInternal`
`[ИСТОЧНИК src/main/java/ru/octomem/cli/Main.java:91-127]`. Существуют **ровно** четыре
режима и два вида параметров:

```text
java -jar octomem-1.0.0.jar [--config ПУТЬ] [--ключ=значение]
java -jar octomem-1.0.0.jar --check-config [--config ПУТЬ] [--ключ=значение]
java -jar octomem-1.0.0.jar --help
java -jar octomem-1.0.0.jar --version
```

`[ИСТОЧНИК src/main/java/ru/octomem/cli/Main.java:99-133,186-215]`.

Правила, реализованные в коде:

| Правило | Деталь | Источник |
|---|---|---|
| `--help` / `--version` | работают **отдельно**: с файлом, переопределениями или другим режимом дают ошибку аргументов | `Main.java:100-102,128-133` |
| `--check-config` | сочетается с `--config` и `--ключ=значение`; проверяет и не запускает сервер | `Main.java:140-143` |
| `--config ПУТЬ` или `--config=ПУТЬ` | ровно один раз; пустой путь и повтор запрещены; путь, начинающийся с `--`, задавайте формой со знаком равенства | `Main.java:104-117` |
| `--ключ=значение` | имя после `--` совпадает с ключом конфигурации (см. §5); каждый ключ не более одного раза; неизвестный ключ — ошибка | `Main.java:110-124` |
| Позиционные аргументы | запрещены | `Main.java:119` |

Вывод режимов `[ИСТОЧНИК Main.java:130-132,141,186-215]`:

- `--version` → `octomem 1.0.0` (код 0).
- `--help` → русская справка с полным списком ключей и границ (код 0).
- `--check-config` при корректной конфигурации → `Конфигурация корректна. Сервер не запущен.`
  (код 0). Проверка **не открывает порт**, не выполняет DNS-запросов, не создаёт рабочих
  потоков и не выделяет память кеша `[ИСТОЧНИК design/config-schema.md:18]`.

## 4. Коды возврата

`main` передаёт код в `System.exit` `[ИСТОЧНИК Main.java:64-66]`.

| Код | Значение | Источник |
|---|---|---|
| 0 | Успех: справка, версия, успешная проверка конфигурации или нормальное завершение работы сервера | `Main.java:132,142,165` |
| 2 | Ошибка аргументов или конфигурации | `Main.java:181-184,136-139` |
| 1 | Ошибка запуска или работы (в т.ч. невозможность привязаться к адресу, автономный отказ транспорта, прерывание ожидания) | `Main.java:166-172` |

`[НЕ ПРОВЕРЕНО]` Коды завершения по сигналам (например, 130/143 на POSIX),
запланированные в `design/D-03-messages-and-exit-codes.md:78-79`, в коде **не
устанавливаются**. Реализован shutdown-hook `octomem-shutdown`, вызывающий `close()`
`[ИСТОЧНИК Main.java:153-154]`; фактический код завершения при сигнале определяется JVM и
оболочкой и здесь не заявляется.

## 5. Ключи конфигурации (ровно 14)

Полный набор и значения по умолчанию заданы в `ConfigLoader.DEFAULTS`
`[ИСТОЧНИК src/main/java/ru/octomem/config/ConfigLoader.java:23-37]`; границы и типы —
в `ConfigLoader.normalize` `[ИСТОЧНИК ConfigLoader.java:162-254]`. Имена ключей
регистрозависимы, алиасов нет.

| Ключ | По умолчанию | Смысл | Границы (проверка) |
|---|---|---|---|
| `listen.address` | `127.0.0.1` | Адрес привязки, числовой литерал | IPv4 ровно 4 октета 0..255 через точки, либо IPv6-литерал; имена хостов, зона `%`, скобки запрещены |
| `listen.port` | `11211` | TCP-порт | `1..65535` |
| `memory.limit` | `67108864` (64 MiB) | Бюджет кеша в байтах (**не** RSS и не heap процесса) | `1..9223372036854775807` |
| `item.maxSize` | `1048576` (1 MiB) | Максимальный размер полной записи (ключ + служебные поля + значение + выравнивание) | `1..2147483647`, и `<= memory.limit` |
| `connections.max` | `1024` | Максимум одновременно принятых соединений | `1..2147483647` |
| `transport.workers` | `max(2, 2 × доступные процессоры)` | Число циклов событий | `1..2147483647` |
| `eviction.policy` | `lru` | Политика вытеснения | допустимо **только** `lru` |
| `expiry.reclaimIntervalSeconds` | `1` | Период фоновой очистки просроченных записей, секунды | `1..9223372036` |
| `protocol.maxLineBytes` | `8192` | Максимальная длина строки команды, байты | `1..2147483647` |
| `protocol.maxChunkBytes` | `65536` (64 KiB) | Максимальная часть ответа, байты | `2..2147483647` |
| `connections.pendingWriteBytes` | `8388608` (8 MiB) | Предел подготовленных, но не записанных байтов на соединение (не предел ответа) | `2..2147483647` |
| `connections.maxInflightCommands` | `16` | Максимум декодированных, но не завершённых команд на соединение | `1..2147483647` |
| `connections.idleTimeoutSeconds` | `0` | Тайм-аут простаивающего соединения, секунды; `0` отключает | `0..9223372036` |
| `log.level` | `info` | Уровень журнала | `error`, `warn`, `info`, `debug` (регистр не важен) |

Значения по умолчанию в этом документе приведены в каноническом виде (десятичные байты),
как их возвращает `ConfigLoader.defaults()`; в файле/CLI допустимы суффиксы `k/K`, `m/M`,
`g/G` с двоичными множителями 1024, 1048576, 1073741824
`[ИСТОЧНИК ConfigLoader.java:232-240]`.

Разбор чисел: только ASCII-цифры `0..9`; ведущие нули допускаются; знаки, дроби,
экспоненты, группировка и не-ASCII цифры запрещены; проверка переполнения выполняется до
умножения на множитель `[ИСТОЧНИК ConfigLoader.java:229-254]`.

Дополнительное перекрёстное правило: `item.maxSize` не должен превышать `memory.limit`
`[ИСТОЧНИК ConfigLoader.java:73-75]`.

`[РЕКОМЕНДАЦИЯ]` Значения по умолчанию не должны неожиданно менять поведение известных
клиентов `[ИСТОЧНИК docs/03-architecture-specification.md:418]`.

## 6. Файл конфигурации

Формат и защитные пределы реализованы в `ConfigLoader.readFile`/`parseLine`
`[ИСТОЧНИК ConfigLoader.java:79-153]` и описаны в `design/config-schema.md`
`[ИСТОЧНИК design/config-schema.md:20-32]`:

- UTF-8, одна пара `ключ=значение` на строку; разделитель — только `=`.
- Пустые строки и строки, начинающиеся (после ASCII-пробелов/табов) с `#` или `!`,
  игнорируются.
- Допустимы LF и CRLF; одиночный CR запрещён; последняя строка может не иметь перевода
  строки.
- BOM допускается **только** первым символом файла; встроенный/повторный BOM запрещён.
- Нет кавычек, escape-последовательностей, продолжений строк, интерполяции `${...}`,
  переменных окружения и включения файлов; обратная косая черта в значении запрещена.
- Неизвестный ключ и повтор ключа отвергаются; пустое значение (после удаления краевых
  пробелов/табов) — ошибка синтаксиса.
- Защитные пределы: файл не более 1048576 байт; физическая строка не более 8192
  UTF-16-единиц `[ИСТОЧНИК ConfigLoader.java:20-21]`.

Пример всех 14 ключей: `design/config-example.properties`
`[ИСТОЧНИК design/config-example.properties]`. В примере `transport.workers` оставлен
комментарием, чтобы не подменять вычисляемое значение числом конкретной машины
`[ИСТОЧНИК design/config-schema.md:22]`.

## 7. Приоритет источников

Приоритет: **аргументы командной строки > файл > значения по умолчанию**
`[ИСТОЧНИК ConfigLoader.java:58-77, docs/03-architecture-specification.md:393]`.
Без `--config` файл не читается `[ИСТОЧНИК Main.java:193, design/config-schema.md:16]`.
Синтаксис файла и имена ключей проверяются даже тогда, когда значение переопределено
через CLI `[ИСТОЧНИК ConfigLoader.java:49-51]`.

## 8. Привязка и порт

- По умолчанию сервер слушает `127.0.0.1:11211` — петлевой адрес
  `[ИСТОЧНИК ConfigLoader.java:24-25]`.
- Привязка к не-петлевому адресу разрешена явной настройкой и сопровождается
  предупреждением `BROAD_BIND` уровня `warn`: «Сервер доступен за пределами локального
  интерфейса. Аутентификации нет.»
  `[ИСТОЧНИК src/main/java/ru/octomem/stats/SafeLogger.java:18, CacheServer.java:124]`.
- `listen.address` принимает только числовой литерал без DNS-разрешения
  `[ИСТОЧНИК ConfigLoader.java:167-189, ServerConfig.java:25]`.

## 9. Память

- `memory.limit` — бюджет **кеша**, а не предел RSS/heap процесса
  `[ИСТОЧНИК ServerConfig.java:34-39, docs/03-architecture-specification.md:349]`.
- Значения хранятся вне кучи Java в страницах распределителя; куча содержит хеш-таблицу,
  служебные структуры и ограниченные буферы
  `[ИСТОЧНИК docs/03-architecture-specification.md:341-344]`.
- Ограничивать RSS только настройкой кеша нельзя; накладные расходы JVM не обещаются
  отсутствующими `[ИСТОЧНИК docs/03-architecture-specification.md:347,349]`.
- `[РЕКОМЕНДАЦИЯ]` Размер процесса (heap/direct/RSS) следует измерять отдельно; лимит
  кеша не равен лимиту процесса `[ИСТОЧНИК docs/java-platform.md:25]`.

## 10. Журнал и уровни детализации

- `log.level` задаёт порог при старте; значения `error`, `warn`, `info`, `debug`
  (регистр не важен, канонизируется в нижний регистр)
  `[ИСТОЧНИК ConfigLoader.java:196-202]`.
- При запуске через `Main` события уровня `INFO`/`DEBUG` пишутся в stdout, `WARN`/`ERROR`
  — в stderr `[ИСТОЧНИК Main.java:146-149]`.
- Фиксированный набор событий и их уровни: `STARTED` (info), `STOPPED` (info),
  `BROAD_BIND` (warn), `CAPACITY` (warn), `START_FAILURE`/`INTERNAL_FAILURE`/
  `TRANSPORT_FAILURE`/`EXPIRY_FAILURE` (error), `COMMAND` (debug)
  `[ИСТОЧНИК SafeLogger.java:15-28]`.
- События `CAPACITY` и `COMMAND` ограничиваются по частоте (не чаще одного раза в
  секунду при наличии часов; при отсутствии часов — один раз)
  `[ИСТОЧНИК SafeLogger.java:69-88]`.
- Журнал **не содержит** значений кеша, ключей и текстов исключений
  `[ИСТОЧНИК SafeLogger.java:14, docs/03-architecture-specification.md:425]`.
- Протокольная команда `verbosity <level>` меняет порог во время работы: `0` → `error`,
  `1` → `info`, `2` и выше → `debug` `[ИСТОЧНИК SafeLogger.java:63-68, CacheCommandDispatcher.java:87]`.

## 11. Примеры

Проверка конфигурации без запуска `[ИСТОЧНИК Main.java:210]`:

```text
java -jar octomem-1.0.0.jar --check-config --config design/config-example.properties --memory.limit=128m
```

Обычный запуск:

```text
java -jar octomem-1.0.0.jar --config octomem.conf
```

Обычный запуск блокируется до остановки процесса; `Ctrl+C` запускает `close()` и
освобождение ресурсов `[ИСТОЧНИК Main.java:163,213, CacheServer.java:184-200]`.
