# 01. Упаковка и поставляемый артефакт

Статус документа: черновик 0.1. Описывает **фактически собранный** артефакт репозитория,
а не заявление о выпуске.

## 1. Координаты и форма поставки

- Maven-координаты: `ru.octomem:octomem:1.0.0`, `packaging=jar`
  `[ИСТОЧНИК pom.xml:15-18]`.
- Итоговый файл: `target/octomem-1.0.0.jar`
  `[ИСТОЧНИК pom.xml:16]`.
- Точка входа (Main-Class из манифеста): `ru.octomem.cli.Main`
  `[ИСТОЧНИК pom.xml:33, 151-158]`.
- Это **не** «толстый» (uber/fat) JAR: отдельные библиотеки в него не вкладываются.
  Манифест, снятый из локального артефакта:
  `Main-Class: ru.octomem.cli.Main`, `Implementation-Version: 1.0.0`, `Java-Version: 25`,
  `Build-Jdk-Spec: 25` `[ДОКАЗАТЕЛЬСТВО target/octomem-1.0.0.jar (META-INF/MANIFEST.MF)]`.
- Имя версии в манифесте совпадает с константой `Main.VERSION = "1.0.0"`
  `[ИСТОЧНИК src/main/java/ru/octomem/cli/Main.java:28]`.

## 2. Команда сборки и закреплённый инструментарий

### 2.1. Команда

Полная проверка, использованная в доказательствах замороженного кандидата (Windows):

```text
mvnw.cmd -B -ntp clean verify -Pcoverage
```

`[ДОКАЗАТЕЛЬСТВО tests/reports/T013/ds/README.md §«Full run», tests/reports/T013/candidate/evidence-matrix-final.md §2]`.
На POSIX-оболочке используется `./mvnw -B -ntp clean verify -Pcoverage`
`[ИСТОЧНИК mvnw, mvnw.cmd]`.

Минимальная сборка только артефакта (без интеграционных проверок) — `mvnw -B -ntp clean package`;
она также создаёт `target/octomem-1.0.0.jar`, но не прогоняет проверку совместимости
и покрытие `[РЕКОМЕНДАЦИЯ]`.

### 2.3. Закреплённая сборка OpenJDK

Платформа мандатно — OpenJDK 25 `[ИСТОЧНИК docs/java-platform.md:3]`. Выбранная в
манифесте совместимости сборка — Eclipse Temurin 25.0.4.1+1 с зафиксированным хешем
архива `[ДОКАЗАТЕЛЬСТВО compatibility-manifest.json, поля `platforms[0]`]`. В этом же
манифесте подтверждение на стенде помечено как
`"verificationStatus": "selected-target-not-yet-verified-on-stand"`
`[ДОКАЗАТЕЛЬСТВО compatibility-manifest.json]` — то есть целевая сборка выбрана, но
испытания на стенде не завершены.

## 3. Свойство «ноль сторонних runtime-зависимостей»

Утверждение: в runtime сервера нет сторонних Java/native-библиотек, только стандартная
библиотека OpenJDK `[ИСТОЧНИК docs/java-platform.md:17]`.

Свойство обеспечивается и проверяется тремя независимыми механизмами:

1. **Запрет зависимостей не-test области.** Плагин enforcer запрещает зависимости
   областей `compile`, `runtime`, `provided`, `system`; объявлены только две зависимости
   области `test` `[ИСТОЧНИК pom.xml:47-69, 94-102]`.
2. **Снимок дерева runtime-зависимостей.** На фазе `prepare-package` плагин dependency
   выгружает дерево области `runtime` в `target/runtime-dependency-tree.json`
   `[ИСТОЧНИК pom.xml:161-179]`; файл присутствует в `target/`
   `[ДОКАЗАТЕЛЬСТВО target/runtime-dependency-tree.json]`.
3. **Содержимое JAR.** В архиве нет вложенных библиотек: перечень записей — `ru/octomem/**`
   и `META-INF/**` (плюс каталог `ru/`), без каталогов вида `lib/`, `BOOT-INF/lib/`
   `[ДОКАЗАТЕЛЬСТВО target/octomem-1.0.0.jar (листинг)]`.

Команды для повторной проверки на чистом стенде `[РЕКОМЕНДАЦИЯ]`:

```text
mvnw.cmd -B -ntp -DskipTests package
jar tf target/octomem-1.0.0.jar
```

`[НЕ ПРОВЕРЕНО]` Наличие нулевых runtime-зависимостей на уровне POM и содержимого JAR
доказано перечисленными механизмами, но полный аудит лицензий и уязвимостей тестовых
зависимостей в рамках этого документа не проводился (он относится к TEST-06/ЧТЗ-09
`[ИСТОЧНИК docs/07-security-operations-release.md:113-115]`). OpenJDK остаётся явно
названной платформой и не «прячется» за формулировкой «ноль зависимостей»
`[ИСТОЧНИК docs/java-platform.md:19]`.

## 4. Поддерживаемые платформы

- **Обязательна OpenJDK 25.** JAR с байткодом 25 не запускается на JDK 21
  `[ИСТОЧНИК docs/java-platform.md:9]`.
- **JDK 21 — только резервный план.** Его введение требует отдельного ADR, адаптации
  исходников/API, **отдельного артефакта** и повторных испытаний; автоматического
  переключения JVM нет; маркировать 21 поддержанной без доказательств запрещено
  `[ИСТОЧНИК docs/java-platform.md:9, docs/01-product-brief.md:74]`.
- **Java 17 исключена** `[ИСТОЧНИК docs/java-platform.md:3, pom.xml:91]`.
- **Используются только свободные сборки OpenJDK**; Oracle JDK и proprietary runtime
  платформами не являются `[ИСТОЧНИК docs/java-platform.md:3]`.
- **Операционная система.** В манифесте выбран Windows 11 (10.0.26200, amd64)
  `[ДОКАЗАТЕЛЬСТВО compatibility-manifest.json, `platforms[0]`]`. Требуются **две**
  доверенные ОС разных правообладателей, отличные от сборочного узла, проверенные на
  реальных стендах `[ДОКАЗАТЕЛЬСТВО compatibility-manifest.json, `platformRequirements`]`.
- **Матрица платформ не выполнена.** `platformRequirements.verificationStatus = "NOT_RUN"`,
  `accessStatus = "unavailable"`; ни одна ОС не заявлена проверенной, TEST-08 не начат
  `[ДОКАЗАТЕЛЬСТВО compatibility-manifest.json; tests/reports/T013/candidate/evidence-matrix-final.md §6]`.

`[НЕ ПРОВЕРЕНО]` Ни одна конкретная комбинация «ОС/CPU/OpenJDK/артефакт» не подтверждена
испытаниями на стенде; нехватка подходящей сборки 25 на доверенной ОС является риском,
а не разрешением объявить 21 проверенной `[ИСТОЧНИК docs/java-platform.md:30]`.
В репозитории есть подготовительный скрипт второй платформы
(`tests/platform/linux/setup.sh` — подготовка Ubuntu 24.04 chroot с закреплённой Linux
JDK 25.0.2); это именно подготовка стенда, а не собранные результаты матрицы платформ,
которая остаётся `NOT_RUN`.

## 5. Что входит и что не входит в фактическую поставку репозитория

**Фактически существует:**

- JAR `target/octomem-1.0.0.jar` `[ДОКАЗАТЕЛЬСТВО]`.
- Пример конфигурации `design/config-example.properties` (14 ключей, `transport.workers`
  закомментирован) `[ИСТОЧНИК design/config-example.properties]`.
- Схема конфигурации `design/config-schema.md` `[ИСТОЧНИК design/config-schema.md]`.
- Дерево runtime-зависимостей `target/runtime-dependency-tree.json` `[ДОКАЗАТЕЛЬСТВО]`.

**Не существует как поставляемый файл (не описывается как поставленное):**

- Скрипты запуска сервера для целевых ОС — как поставляемый элемент отсутствуют. В
  репозитории есть только служебные скрипты тестовой среды и прототипа
  (`tests/environment/**`, `tests/instrumentation/**`, `tests/platform/linux/setup.sh`,
  `exp/prototypes/P001/**`); они готовят и обслуживают стенды и не являются скриптами
  запуска сервера или частью поставки. Состав скриптов запуска запланирован в общих
  требованиях к поставке `[ИСТОЧНИК docs/02-general-technical-specification.md:189-200]`,
  но в поставке их нет.
- SBOM в открытом формате, файл лицензии и `NOTICE` сторонних компонентов, контрольные
  суммы артефактов — как отдельные поставляемые файлы отсутствуют; их наличие
  запланировано `[ИСТОЧНИК docs/07-security-operations-release.md:85-96]`.
- Файл конфигурации по умолчанию `octomem.conf` как файл поставки — отсутствует; есть
  только пример `design/config-example.properties` `[ИСТОЧНИК design/config-schema.md:22]`.

`[НЕ ПРОВЕРЕНО]` Воспроизводимость сборки «повторная сборка даёт те же артефакты»
заявлена требованием `[ИСТОЧНИК docs/07-security-operations-release.md:97-99]`, но
независимая повторная сборка и сравнение здесь не выполнялись.

## 6. Рекомендации по фиксации артефакта перед поставкой

`[РЕКОМЕНДАЦИЯ]` Перед любой поставкой:

1. Собрать артефакт закреплённым wrapper'ом на закреплённой OpenJDK 25.
2. Зафиксировать SHA-256 и размер полученного JAR.
3. Повторить сборку из чистого каталога и сравнить хеши; расхождения метаданных
   объяснить отдельно (требование `[ИСТОЧНИК docs/07-security-operations-release.md:99]`).
4. Проверить листинг JAR и `target/runtime-dependency-tree.json` на отсутствие сторонних
   библиотек.
5. Выполнить чистую установку и запуск на стенде (см. документ 02).

Эти шаги относятся к эксплуатационной подготовке и не отменяют открытые пункты приёмки
(`docs/09-acceptance-and-registry-readiness.md`).
