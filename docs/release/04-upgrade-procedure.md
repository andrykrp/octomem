# 04. Процедура обновления

Статус документа: черновик 0.1. Процедура описывает замену артефакта; она **не**
подтверждает готовность выпуска и не заменяет приёмку.

## 1. Область и предпосылки

- Обновление в 1.0 — это **замена JAR** при неизменном внешнем файле конфигурации.
  Данные кеша живут только в памяти и при обновлении, выполняемом через перезапуск,
  **не сохраняются** `[ИСТОЧНИК docs/01-product-brief.md:13, NG1; docs/07-security-operations-release.md:83]`.
- Обновление выполняется как остановка → замена артефакта → запуск
  `[ИСТОЧНИК docs/07-security-operations-release.md:81]`.
- Новый артефакт требует **OpenJDK 25**; JAR с байткодом 25 не запускается на 21
  `[ИСТОЧНИК docs/java-platform.md:9]`.
- Онлайн-активации, обязательных внешних сервисов и обращения к сети при обновлении нет
  `[ИСТОЧНИК docs/07-security-operations-release.md:56]`.

`[НЕ ПРОВЕРЕНО]` В репозитории нет файла release notes / changelog для будущих версий,
нет опубликованных контрольных сумм и SBOM (документ 01 §5). Приведённые ниже шаги —
эксплуатационная процедура `[РЕКОМЕНДАЦИЯ]`, а не гарантия кода.

## 2. Ожидания совместимости

Схема версионирования проекта — `major.minor.patch`
`[ИСТОЧНИК docs/07-security-operations-release.md:107-109]`:

| Компонент версии | Ожидание совместимости |
|---|---|
| `patch` | Исправляет дефекты без изменения контракта протокола и значений по умолчанию |
| `minor` | Добавляет возможности, не нарушая существующий (проверенный) профиль |
| `major` | Допускает несовместимость и требует инструкции по переходу |

Дополнительно:

- Набор из 14 ключей конфигурации фиксирован; добавление ключей требует ADR
  `[ИСТОЧНИК docs/03-architecture-specification.md:395-397]`.
- Неизвестный ключ в файле или CLI отвергается, поэтому конфигурация должна быть
  совместима с **новой** версией до запуска
  `[ИСТОЧНИК src/main/java/ru/octomem/config/ConfigLoader.java:155-160]`.
- Повторяющиеся ключи в новом наборе изменений недопустимы.

`[НЕ ПРОВЕРЕНО]` Никакие переходы между версиями не выполнялись: в проекте существует
только версия 1.0.0. Ожидания совместимости — это документированная политика, а не
проверенный процедурой факт.

## 3. Что сохраняется, а что нет

| Объект | При обновлении |
|---|---|
| Содержимое кеша | **Не сохраняется.** Теряется при перезапуске `[ИСТОЧНИК docs/07-security-operations-release.md:83]` |
| Счётчики `stats` | **Не сохраняются.** Счётчики начинаются с нуля в новом процессе `[ИСТОЧНИК docs/03-architecture-specification.md:9, AtomicStatsRegistry.java]` |
| Токены `cas` | **Не сохраняются** между процессами (счётчик версий живёт в процессе) `[ИСТОЧНИК DefaultCacheEngine.java:122]` |
| Состояние `flush_all` | **Не сохраняется** (перезапуск) |
| `uptime` | Начинается заново |
| Внешний файл конфигурации | Сохраняется как файл ОС; должен оставаться валидным для новой версии |
| Правила ОС/сети (firewall, сегмент) | Сохраняются за пределами процесса |

`[РЕКОМЕНДАЦИЯ]` Приложение обязано переживать потерю кеша как обычный промах и
прогревать кеш запросами к источнику истины
`[ИСТОЧНИК docs/01-product-brief.md:13, docs/07-security-operations-release.md:119-121]`.
Учтите всплеск нагрузки на основную базу при холодном старте.

## 4. Порядок обновления

`[РЕКОМЕНДАЦИЯ]` Шаги ниже проверяемы и не заявляют прохождения приёмки.

1. **Зафиксировать текущую версию и артефакт.** Снять `version` через протокол (ожидаемая
   строка `VERSION 1.0.0 (octomem)`) `[ИСТОЧНИК compatibility-manifest.json]` или выполнить
   `java -jar octomem-1.0.0.jar --version`; скопировать текущий JAR и вычислить его SHA-256.
2. **Остановить сервер штатно** (SIGINT/SIGTERM). Дождаться события `STOPPED`
   `[ИСТОЧНИК CacheServer.java:197]` и кода возврата 0 при нормальной остановке
   `[ИСТОЧНИК Main.java:165]`.
3. **Заменить артефакт.** Разместить новый JAR на месте старого (или использовать новый
   путь в команде запуска).
4. **Проверить артефакт.** Сверить SHA-256 нового JAR с опубликованным (когда он будет
   опубликован). `[НЕ ПРОВЕРЕНО]` На момент документа опубликованных контрольных сумм нет.
5. **Проверить версию и конфигурацию без запуска:**
   `java -jar <новый>.jar --version` и
   `java -jar <новый>.jar --check-config --config <файл>`
   `[ИСТОЧНИК Main.java:128-143]`. Успешная проверка печатает
   `Конфигурация корректна. Сервер не запущен.` и возвращает 0.
6. **Запустить сервер** и убедиться, что открыт слушающий порт
   `[ИСТОЧНИК CacheServer.java:116-132]`.
7. **Проверить на протоколе:** `version` возвращает новую версию; `stats` отвечает
   полным набором полей `[ИСТОЧНИК CacheCommandDispatcher.java:157-163]`.
8. **Выполнить прикладной сценарий пилота** и сверить `stats`: попадания, промахи,
   вытеснения, память `[ИСТОЧНИК docs/04-protocol-compatibility-specification.md:294-302]`.
9. **Наблюдать** `evictions`, `bytes`/`limit_maxbytes`, `get_hits`/`get_misses`,
   `curr_connections` (документ 03 §4.1).

## 5. Откат

Если после обновления наблюдается регрессия, верните предыдущий артефакт по документу
[05-rollback-procedure.md](05-rollback-procedure.md). Помните: ни обновление, ни откат
**не** восстанавливают содержимое кеша — оно не сохраняется между запусками.

## 6. Ограничения процедуры

- `[НЕ ПРОВЕРЕНО]` Обновление с сохранением состояния невозможно: постоянного хранения нет.
- `[НЕ ПРОВЕРЕНО]` Автоматическое обновление отсутствует
  `[ИСТОЧНИК docs/07-security-operations-release.md:35]`.
- `[НЕ ПРОВЕРЕНО]` Процедура не выполнялась на чистом стенде в рамках этого документа;
  требование «инструкция на чистом стенде» остаётся открытым
  `[ИСТОЧНИК docs/02-general-technical-specification.md:204]`.
