  страница документации `https://www.rosalinux.ru/docs/`.
- Карточка №1999 («ОС РОСА КОБАЛЬТ»), https://reestr.digital.gov.ru/reestr/303349/,
  те же реквизиты правообладателя; описание относит продукт к RHEL 7-совместимой
  линейке. Это отдельный продукт, не десктоп ROSA Fresh.
- Карточки `ROSA Enterprise Desktop` (https://reestr.digital.gov.ru/reestr/306290/) и
  `ROSA Enterprise Linux Desktop` (https://reestr.digital.gov.ru/reestr/306293/)
  получают по HTML сообщение `Доступ к реестровой записи ограничен до обновления
  сведений правообладателем!` — детали этих записей публично не раскрыты; из выдачи
  известны только наименование, владелец, класс `02.09`, дата `03.12.2018` и номера
  (`4940` и `4943` соответственно).

**Запись может относиться к продуктовой линейке, а не к версии 13.2.** В реестровых
карточках линейки ROSA не указана версия «13.2» (карточка №1607 упоминает только
базовую платформу `2021.1`). Поэтому реестровая запись не подтверждает регистрацию
именно редакции 13.2 и тем более именно дистрибутива ROSA Fresh.

**Прямая запись для «ROSA Fresh» не найдена использованными запросами.** Ни поиск по
названию, ни вендорская страница
`https://rosa.ru/licenses-certifs/` не связывают ROSA FRESH с реестровой записью:
на этой странице блок `ROSA FRESH` содержит только описание и не содержит ссылки
«Выписка из Реестра отечественного ПО», тогда как блоки `РОСА «ХРОМ»
(ROSA ENTERPRISE DESKTOP)`, `РОСА «КОБАЛЬТ»`, `ROSA Enterprise Desktop`,
`ROSA Enterprise Linux Desktop/Server`, `ROSA VIRTUALIZATION` такие ссылки содержат.
Страница `https://rosa.ru/rosa-fresh-13/` описывает продукт как «Бесплатная домашняя
ОС РОСА «ФРЕШ»», создаваемую сообществом, без реестровых реквизитов. Это косвенно
указывает, что ROSA Fresh как отдельный продукт, вероятно, не включался в реестр,
однако **прямого отрицания вендор также не публикует**, поэтому вывод формулируется как
«запись для ROSA Fresh не найдена», а не «ROSA Fresh не зарегистрирована».

**Правообладатель — смена организационно-правовой формы.** Текущие карточки портала
(2026) указывают АО «НТЦ ИТ РОСА» (ИНН `7735201059`, ОГРН `1237700702304`), а
вендорские выписки 2022 г. на те же записи — ООО «НТЦ ИТ РОСА»
(ИНН `7703764066`, ОГРН `1127746162279`). Обе величины приведены дословно; какая из
них является актуальной юридической стороной на дату иного использования — вне рамок
этого документа.

**Вендор не публикует SHA-256.** Подтверждено: в каталогах зеркала присутствуют только
файлы `.md5sum`, `.sha1sum`, `.torrent` (см. `raw/mirror_rosa_fresh13_plasma6.html`
и др.), а страница загрузок `https://rosa.ru/rosa-linux-download-links/` приводит
исключительно md5sum. SHA-256 доступен только как локально вычисленный или ранее
записанный в проекте, но не как опубликованное вендором значение.

  правообладателю**. Файл `raw/reestr_owner_inn_7735201059.html`
  (`?OWNER_INN=7735201059`) содержит **9** карточек (`data-href="/reestr/…"`), а
  `raw/reestr_owner_name.html` (`?OWNER_NAME=НТЦ ИТ РОСА`) — те же **9** карточек:
  id `3508161`, `2124179`, `2099894`, `1790991`, `1306956`, `1306948`, `306441`,
  `303349`, `302957`. Это ровно записи правообладателя с указанным ИНН, и среди них
  **ни одной «ROSA Fresh»**. Файл `raw/reestr_prodname_rosa.html` (`?PROD_NAME=РОСА`)
  содержит **20** карточек, среди которых есть неточные совпадения по подстроке «роса»
  (например, «опроса», «Росатом»); «ROSA Fresh» отсутствует и там. Во всех трёх файлах
  строки `Fresh`/`Фреш` не встречаются. Таким образом выборка по правообладателю
  подтверждает отсутствие записи для ROSA Fresh среди записей этого владельца.
  (Ранее в документе эти страницы были ошибочно охарактеризованы как неотфильтрованный
  общий каталог; утверждение исправлено по сохранённым raw-файлам.)
- Живая повторная проверка портала координатором и независимым ревьюером 2026-09-25
  в 14:0x–14:2xZ **не удалась** из-за сброса соединений/недоступности портала. Поэтому
  негативный результат C1 опирается на **сохранённые raw-выдачи** и полный перечень
  поисковых запросов, а не на повторный live-запрос.
- Два вендорских PDF (`reestr_chrome.pdf`, `reestr_red.pdf`) отдаются сервером с
  цепочкой сертификатов, не проходящей проверку в PowerShell 5.1; они получены
  `curl -k` с HTTP 200 (обход проверки сертификата явно записан в
  `raw/meta-fetch-log.tsv`). Содержимое PDF согласуется с данными карточек портала,
  но канал получения этих двух файлов не был проверен штатной валидацией TLS.
- Реестр — государственный информационный ресурс; приведённые значения являются
  цитатами из него, однако документ не делает юридических выводов.

**Чего документ НЕ утверждает.** Ничего из следующего не утверждается: доверенный
статус ОС; юридическая сила; отсутствие ограничений на использование; подлинность
вендора сверх факта совпадения опубликованного MD5; соответствие конкретной версии
13.2 какой-либо реестровой записи; отсутствие иных релевантных записей, не найденных
использованными поисковыми запросами.

**Вопрос о том, какая запись «соответствует продукту».** Поскольку записи с
наименованием «ROSA Fresh» не найдено, однозначное сопоставление невозможно. Наиболее
близкие к десктопной ОС ROSA записи: `ОС РОСА ХРОМ` (№1607), которую сам вендор
подписывает как «РОСА «ХРОМ» (ROSA ENTERPRISE DESKTOP)», и `ROSA Enterprise Desktop`
(№4940). Обоснование ограничивается этим совпадением по вендорской подписи и классу
`02.09`; равенство ROSA Fresh и указанных продуктов из первичных источников **не**
следует.
