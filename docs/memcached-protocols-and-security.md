Это ограниченные инженерные доказательства, не универсальная или реестровая квалификация.

Состояние реализации на 25.10.2026: classic text, binary и meta работают на одном TCP-порту и общем хранилище. Семейство binary определяется первым байтом соединения; classic и meta можно чередовать в одном ASCII-соединении. Данные и CAS общие между семействами. Это не заявление полной совместимости со всеми расширениями Memcached/Couchbase.

## Проверяемые семейства

- Binary core: GET/GETK/GAT/GATK/TOUCH, SET/ADD/REPLACE, APPEND/PREPEND, DELETE, INCR/DECR с initial/exptime, FLUSH, NOOP, VERSION, STAT и QUIT, включая применимые quiet-варианты, opaque и CAS. Opcode VERBOSITY 0x1b не поддерживается выбранным core-эталоном1.6.45 и не изображается поддержанным.
- Meta: `mg`, `ms`, `md`, `ma`, `me`, `mn`; флаги значений/метаданных, CAS compare/override, opaque/key reflection, quiet, бинарные base64-ключи, TTL, режимы storage/arithmetic, vivify/recache W/Z, stale/tombstone. Точные сочетания сверяются с pinned1.6.45; не каждый возможный cross-product доказан отдельным тестом.
- Classic: ранее поддержанный профиль и его регрессии сохранены. Дедупликация повторных multi-get ключей, ограничение длины строки и геометрия item.maxSize остаются отдельными известными отличиями, а не скрываются расширением протоколов.

## По умолчанию

Адрес `127.0.0.1:11211`, authentication и TLS выключены. Прежние четырнадцать defaults не изменены. Для обычного клиента этого профиля меняется адрес сервера, но режим протокола и сериализатор клиента сохраняются. Нельзя отключать существующие TLS/auth ради успешного пилота.

## SASL PLAIN

Пример файла конфигурации (секретов в примере нет):

```properties
auth.mode=sasl
auth.file=C:/secure/octomem/users.txt
```

`auth.file` — UTF-8, строки `username:password`; пустые строки и строки с `#` игнорируются. Файл должен быть доступен только служебной учётной записи и администраторам. Не добавляйте его в проект, архивы доказательств или систему контроля версий. Максимум65536байт; username1–128 печатных ASCII-байт без пробелов, password до1024 UTF-8байт. Пустые/неверные/дублирующие записи и повреждённый UTF-8 отклоняются до открытия listener.

Поддерживается механизм **PLAIN**, не весь набор механизмов Cyrus SASL. Клиент использует binary LIST_MECHS/AUTH, успешная аутентификация относится только к этому соединению. Неверный пароль не даёт доступа к кешу; неаутентифицированная cache-команда получает отказ и закрывает соединение. VERSION доступен как в выбранном эталоне. Пароли не принимаются отдельным параметром CLI и не выводятся в ошибки/статистику.

## Текстовая аутентификация

```properties
auth.mode=text
auth.file=C:/secure/octomem/users.txt
```

Первой командой клиент посылает совместимый fake SET, тело которого — `username password`. Успешный ответ STORED разрешает последующие classic/meta команды. До этого fake SET не записывает credentials в кеш. Это отдельный режим, не автоматический fallback с SASL.

## TLS 1.2/1.3

```properties
tls.keyStore=C:/secure/octomem/server.p12
tls.keyStorePasswordFile=C:/secure/octomem/keystore-password.txt
auth.mode=sasl
auth.file=C:/secure/octomem/users.txt
```

PKCS12 должен содержать закрытый ключ сервера и цепочку сертификатов. Файл пароля содержит пароль, допускается один завершающий перевод строки. Ошибка файлов/пароля/ключа прерывает запуск; перехода к plaintext нет. Клиент должен проверять цепочку и имя сервера. Self-signed сертификаты и test-only trust contexts используются только в тестах, не предлагаются для production.

PLAIN/text на внешнем bind без TLS запрещены при запуске. TLS-настройки могут применяться и без парольной аутентификации. Клиентские сертификаты/mTLS и внешняя auth-база сейчас не заявлены.

Все ключи можно задавать как `--ключ=значение` либо в UTF-8 конфигурации. `--check-config` проверяет загрузку security-материалов, не открывая listener. При безопасном завершении TLS передаётся close_notify; при аварии/неверном кадре допускается abort. Делегированные криптографические задачи исполняются в ограниченном пуле, не на NIO owner loop; charge соединения удерживается до завершения зависимой задачи. Невозвращающаяся задача JDK-провайдера может задержать окончательное завершение сервера: это не обещание жёсткого shutdown timeout для произвольного провайдера.

## Проверка миграции

1. Зафиксировать версию клиента, протокол, auth/TLS, сериализатор, flags, TTL, размер записей и список серверов.
2. В тестовом контуре изменить только адрес, сохранив защиту и прикладную логику.
3. Проверить запись/чтение/удаление/CAS/счётчики/expiry, quiet pipelines, reconnect и invalid credentials.
4. Сравнить статистику и поведение под штатной нагрузкой отдельно от wire-конформности.
5. Только после проверки планировать переключение и rollback; кеш не является долговременным источником данных.

Доказательства этого изменения находятся в `tests/reports/protocol-expansion-20261025/`: независимые TCP/engine/codec/SSL lifecycle tests, source archives, полные coverage-прогоны, pinned Memcached differential и пилоты настоящих Python-библиотек. Текущие результаты и hash финальной сборки уточняются в checkpoint `run_fb08f2b2d70d`; старые релизные результаты автоматически не переносятся.

## Unix-domain socket и UDP

`listen.unixSocket=/absolute/private-directory/octomem.sock` включает Unix-domain listener вместо TCP. Он использует тот же codec/engine и поддерживает classic/meta/binary. Родительский каталог должен быть доступен только нужным пользователям. Существующий путь, в том числе symlink, не удаляется и не перезаписывается. После остановки сервер **не удаляет** socket entry: оператор проверяет остановку и управляет очисткой своего приватного каталога. Это сознательно исключает неатомарную схему stat→delete, способную удалить подменённый файл. На неподдерживаемой платформе запуск завершается ошибкой, без TCP fallback. TLS поверх этого Unix listener не включается; режим auth можно использовать отдельно.

`listen.udpPort=11211` дополнительно к TCP включает UDP **только на numeric loopback**, по умолчанию он выключен. UDP запрещён вместе с auth/TLS или Unix listener. Он не аутентифицирован и не предназначен для внешнего сетевого доступа. Поддерживаются classic/meta/binary, один packet запроса; sequence/reserved входного заголовка игнорируются как в1.6.45, total≠1 молча отбрасывается. Ответы фрагментируются по1392байта payload, с исходным request ID. Максимальный суммарный ответ —1MiB, включая protocol framing; превышение даёт ограниченную ошибку вместо частичного успешного ответа. Ровно1MiB проверено отдельной регрессией. Доставка UDP не гарантируется.

Полнота кадров датаграммы проверяется до выделения payload/native-записи: оборванный packet не может использовать объявленную огромную длину для преждевременного выделения или вытеснения. Fixed worker graph, ingress и line учитываются в логических бюджетах; неожиданный сбой worker переводит общий lifecycle в ошибку. Эти ограничения отличаются от произвольного сетевого Memcached-профиля и должны быть учтены при миграции.

## Ещё не заявлено

Внешний UDP, multi-packet UDP-запросы, административные watch/lru_crawler/shutdown и Couchbase/TAP расширения не поддержаны. Производительность, 72-часовая устойчивость, квалификация доверенных ОС и юридическая готовность реестра требуют отдельного актуального набора доказательств. Эта страница не даёт разрешения на deployment и не выдаёт локальные тесты за реестровую приёмку.
