# octomem: разбиение работ и задачи агентов

Версия 0.1 от 14.09.2026. Документ для координатора агентов.

Уточнение 0.2 от 14.09.2026: таблицы `ЗАД-*` и этапы этого документа сохранены как историческое разбиение, не как исполняемая очередь. Текущие задачи и зависимости находятся в [tasks/00-index.md](../tasks/00-index.md) и карточках `tasks/`, `tests/`, `design/`, `security/`, `exp/`. Не создавать вторую очередь по старым ID. Соответствие наборов `Т-*` карточкам `TEST-*` задано в [tests/00-index.md](../tests/00-index.md).

## 1. Принципы декомпозиции

1. **Сначала интерфейсы, потом код.** Задачи ЗАД-004 и ЗАД-005 фиксируют контракты из [документа 03](03-architecture-specification.md). До этого параллельная разработка не начинается.
2. **Один владелец на пакет.** В один момент пакет правит один агент. Пересечение по файлам запрещено.
3. **Тесты отдельно от реализации.** Наборы Т-01…Т-09 пишут агенты, не являющиеся авторами проверяемой подсистемы.
4. **Запрещено ослаблять критерии.** Агент не может менять ожидаемые результаты тестов, удалять проверки или сужать обязательный профиль. Изменение критерия — только через координатора и ADR.
5. **Каждая задача заканчивается доказательством.** Компиляция, свои тесты, отчёт, отсутствие нарушений правил зависимостей.
6. **Маленькие задачи.** Задача должна завершаться за один цикл работы агента и иметь проверяемый результат.

## 3. Порядок и зависимости

Обобщённый порядок этапов:

```text
M0 -> M1 -> M2 -> M3 -> M4 -> M5 -> M6 -> M7
```

Исторические зависимости раздела 4 объясняют исходную декомпозицию. Для текущего планирования используются только актуальные карточки и порядок из [tasks/00-index.md](../tasks/00-index.md); готовность требует закрытия зависимостей карточки, не прохождения старой последовательности M0–M7.

## 5. Образец подробной карточки

### ЗАД-011. Команды записи и `cas`

**Цель.** Реализовать команды записи и условную запись по контракту [04](04-protocol-compatibility-specification.md#4-команды-записи).

**Вход.** Декодер (ЗАД-008), кодировщик (ЗАД-009), реализация `CacheEngine` (ЗАД-034) вместе с версиями и атомарностью (ЗАД-018), модель записи (ЗАД-004).

**Выход.** Обработчики `set`, `add`, `replace`, `append`, `prepend`, `cas`, покрытые тестами.

**Требования.** ЧТЗ-02-R03, R09, R10, R11, R12; ЧТЗ-05-R03, R04, R06, R09, R10.

**Проверка.** Т-01 по соответствующим командам; unit-тесты на все ответы и границы `exptime`.

**Критерий готовности.** Компиляция, свои тесты зелёные, строки ответов совпадают с 04, нет изменений чужих пакетов.

**Ограничения.** Не менять интерфейс `CacheEngine`. Не добавлять мета-команды. Не ослаблять проверки размера записи.

**Роль.** Агент-протокол.

## 6. Правила координации агентов

1. **Владение.** Координатор назначает пакет одному агенту. Параллельная правка одного пакета запрещена.
2. **Заморозка контрактов.** Изменение интерфейса из 03 возможно только через ADR; после заморозки — отдельная задача на миграцию.
3. **Проверка независимым агентом.** Реализацию принимает агент, не писавший её код. Для обязательного профиля тесты пишет третья сторона. Прямое ревью одним агентом по отдельному поручению не следует выдавать за эту независимую приёмку реализации.
4. **Запрет на подмену успеха.** Любая попытка достичь `PASS` изменением ожидаемых значений, удалением тестов или сужением профиля считается провалом задачи.
5. **Отчётность.** Каждая задача сдаёт: изменённые файлы, инструкцию запуска, результат тестов, известные ограничения.
6. **Стоп-условия.** Необъяснённое расхождение с эталоном, падение, утечка памяти, нарушение атомарности — остановка задачи до разбора.
7. **Лимит цикла.** Если задача не сходится за отведённый цикл, она возвращается координатору с описанием блокера, а не закрывается частично.

## 7. Что считается завершённым продуктом

Продукт считается завершённым, когда одновременно выполнено:

- Все задачи M0–M6 закрыты и приняты независимо.
- Т-01…Т-09 пройдены, обязательные тесты без пропусков.
- Известные отличия зафиксированы и одобрены.
- Поставка воспроизводима и устанавливается по документации.
- Реестровый комплект M7 собран.

Только после этого начинается подготовка заявки. Регистрация не гарантируется и не является частью инженерной готовности.
