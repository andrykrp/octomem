# Публикация исходного дерева

Владелец указал `https://github.com/andrykrp/octomem.git` и разрешил commit/push. При первичной проверке remote не содержал refs, локальной Git-истории не было; создаётся первоначальная ветка main, без перезаписи существующих коммитов.

## Состав

Публикуются Java-исходники, независимые тесты, Maven Wrapper/POM, манифест возможностей, спецификации и переносимые инструменты проверки. Ни двоичный сервер, ни исходники Memcached, ни установленные JDK и локальные зависимости в дерево не включаются. Включение документа не означает юридическую приёмку или разрешение на production deployment.

`.gitignore` исключает локальные toolchains, target, сырые отчёты/архивы/дампы, сессии агентов, секреты/сертификаты, машинно-зависимые scripts старых стендов. Исключённые материалы остаются на диске: это не удаление или пересоздание доказательств. Ссылки старых документов на `tests/reports/`, `tasks/reports/` и `.opencode/` обозначают локальные доказательства и могут отсутствовать в публичном checkout. Публикуемые summaries с хешами — описания результатов, не замена недоступных raw-артефактов.

## Проверка нового checkout

Использовать OpenJDK25 и Maven Wrapper (`./mvnw`, `mvnw.cmd` на Windows). Первый запуск wrapper скачивает фиксированные build/test зависимости; серверный JAR остаётся без сторонних runtime-зависимостей. **Полный `clean verify -Pcoverage` пока не самодостаточен в новом checkout:** `CompatibilityManifestIT` проверяет также локальные pinned reference tools и evidence paths из манифеста. Они не публикуются автоматически вместе с исходниками, поэтому без отдельно подготовленного квалификационного контура этот gate ожидаемо завершится ошибкой. Нельзя назвать отсутствие этих файлов успешной проверкой или отключать gate ради зелёной сборки. Переносимая подготовка такого контура — отдельная открытая задача.

Для экспериментов и reference differential необходим Memcached1.6.45; он не является частью реализации/поставки. Команда сборки и описанный в отчётах PASS относятся к подготовленному локальному окружению, а не к уже проверенному чистому GitHub checkout.

Последний опубликованный статус проверок берётся из датированного отчёта, а не из факта commit/push. Не ослаблять тест10 000соединений, coverage и прочие обязательные критерии из-за ограничений локального стенда. Создание Git-истории не означает выпуск1.0 или готовность к реестру.
