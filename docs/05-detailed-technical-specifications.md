## ЧТЗ-01. Транспорт и соединения

**Цель.** Принимать TCP-соединения, читать и писать байты, обеспечивать изоляцию соединений и неблокирующую работу.

**Владелец.** Пакет `ru.octomem.transport`.

**Вход.** Конфигурация адреса, порта, числа циклов событий, максимума соединений.

**Выход.** Запущенный слушатель, обработка чтения и записи, корректное закрытие.

**Использует.** `ProtocolDecoder`, `ProtocolEncoder`, `CacheEngine`, `StatsRegistry`.

**Требования.**

| ID | Требование |
|---|---|
| ЧТЗ-01-R01 | Привязка к адресу и порту из конфигурации; понятная ошибка при занятом порту |
| ЧТЗ-01-R02 | Один поток-акцептор и заданное число циклов событий на `java.nio` |
| ЧТЗ-01-R03 | Соединение закреплено за одним циклом; порядок команд сохраняется |
| ЧТЗ-01-R04 | Неблокирующее чтение и запись; частичная запись продолжается по `OP_WRITE` |
| ЧТЗ-01-R05 | Подготовленные, но не записанные байты ограничены `connections.pendingWriteBytes`; части выдаются с обратным давлением |
| ЧТЗ-01-R06 | Ограничение числа соединений `connections.max`; лишние отклоняются |
| ЧТЗ-01-R07 | Ограничение размера входного буфера и защита от бесконечного роста строки |
| ЧТЗ-01-R08 | Ошибка одного соединения не влияет на другие |
| ЧТЗ-01-R09 | Корректное закрытие по `quit`, по ошибке и по остановке сервера |
| ЧТЗ-01-R10 | Учёт соединений и прочитанных/записанных байтов в статистике |
| ЧТЗ-01-R11 | Мягкое ограничение времени ожидания простаивающего соединения (настраиваемое, по умолчанию выключено) |
| ЧТЗ-01-R12 | Приостановка чтения из сокета при заполненной очереди или достижении `connections.maxInflightCommands` |
| ЧТЗ-01-R13 | Декодирование не более одной команды за шаг и не более лимита незавершённых команд |
| ЧТЗ-01-R14 | Body ingress `max(item.maxSize + 32, min(memory.limit, 64 MiB))`, control `544 * 2 * connections.max`, необязательный outbound burst `min(memory.limit, 64 MiB)` отдельно от native и локальных лимитов; checked long/атомарный reserve до allocation, release/cancel/error/disconnect/shutdown ровно один раз (ADR-016 §5 F1/F2) |
| ЧТЗ-01-R15 | Весь допустимый payload+32 резервируется до allocation/bodyread, один byte[] без роста/old+new; отсутствие допуска немедленно выбирает OOM с drain тела+CRLF через собственную scratch lane до ошибки/pipeline. Noreply только по грамматике, неверный terminator закрывает невосстановимый поток. MaxLine и itemMax сохранены, eager itemMax на соединение запрещён |
| ЧТЗ-01-R16 | До регистрации соединение резервирует собственные receive/discard512 и transmit512 с overhead32 каждый; lazy allocation, безопасный отказ допуска. Нормальные/ошибочные ответы и stats форматируются частями min(512,maxChunk) через transmit независимо от burst pool; CRLF2 работает при tiny memory.limit, round-robin с конечным бюджетом без spin/unlimited callbacks |

**Обработка ошибок.** `IOException` закрывает только своё соединение. Полная собственная transmit lane вызывает локальное backpressure; отсутствие burst pool переключает на lane, не блокирует нормальные ответы/ошибки здоровых клиентов. Body admission failure вызывает bounded reject/drain, не ожидание с частичным резервом. Ошибка, отмена и shutdown закрывают снимки и освобождают резервы идемпотентно; это не обещание пережить произвольный JVM OOME.

**Запрещено.** Глобальные блокировки на время ввода-вывода, блокирующие операции в цикле событий, скрытое создание потоков на соединение.

ЧТЗ-01-R17 (M1): charge `2L * L + 256` для int L=maxLine, perconn `satMul(maxInflight,charge)`, global `satMul(connections.max,perconn)`. Только LIMIT насыщаются до Long.MAX_VALUE без config rejection/урезания публичных лимитов, CAS actual reserve проверяет `charge <= limit-used`, без насыщения плат/счётчиков. Slot reserve до чтения; full pipeline отключает OP_READ без body reserve ради slot, control продолжает ответы. Пять heap-пулов отдельно от native, aggregate ceiling не выделяется и не гарантирует RSS.

ЧТЗ-02-R21 (M2): Command.keys() возвращает engine.KeySequence, protocol реализует существующее ребро к engine. Size одним линейным scan считает N; forEachKey(engine.KeyVisitor) передаёт immutable borrowed backing/offset/length до command release. Нет perkey arrays/views/List/starts/offset arrays/getKey byte[]/рекурсии, проходы линейные без O(N²). Raw line геометрически растёт до L, old+new payload≤2L, максимум два header/alignment64 и wrapper/parser/cursor128 помещаются в overhead256; final backing не shrink-copy. Сначала N, затем snapshot reserve/allocation и sequential flat-key fill, обе платы до handoff/release, max key250/дедупликация/defaults сохранены. Тестовый List adapter вне production budget не обязательный API (ADR-016).

**DoD.** Компиляция, unit-тесты транспорта, локальная проверка отсутствия роста потоков при 10 000 соединений, отчёт по памяти. **Трассировка.** Т-03, Т-04.

## ЧТЗ-02. Протокол и команды

**Цель.** Разбирать текстовые команды Memcached и формировать точные ответы.

**Владелец.** Пакет `ru.octomem.protocol`.

**Вход.** Байты от транспорта, результаты вызовов движка.

**Выход.** Готовые команды и байты ответов.

**Требования.**

| ID | Требование |
|---|---|
| ЧТЗ-02-R01 | Потоковый разбор без предположения о границах TCP-сегментов |
| ЧТЗ-02-R02 | Поддержка команд чтения `get`, `gets`, `gat`, `gats` |
| ЧТЗ-02-R03 | Поддержка команд записи `set`, `add`, `replace`, `append`, `prepend`, `cas` |
| ЧТЗ-02-R04 | Поддержка `delete`, `incr`, `decr`, `touch`, `flush_all` |
| ЧТЗ-02-R05 | Поддержка `stats`, `stats items`, `stats slabs`, `stats reset` |
| ЧТЗ-02-R06 | Поддержка `version`, `verbosity`, `quit` |
| ЧТЗ-02-R07 | Суффикс `noreply` подавляет все ответы команды, кроме нарушения кадрирования |
| ЧТЗ-02-R08 | Точные строки ошибок из 04, раздел 7 |
| ЧТЗ-02-R09 | Корректный разбор `exptime`, включая относительный и абсолютный режимы |
| ЧТЗ-02-R10 | Проверка ключа: длина до 250 байт, без пробелов и управляющих символов |
| ЧТЗ-02-R11 | Проверка `flags` как 32-битного беззнакового числа |
| ЧТЗ-02-R12 | Чтение и отбрасывание блока данных при превышении размера записи |
| ЧТЗ-02-R13 | Конвейер: несколько команд из одного сегмента обрабатываются последовательно, по одной за вызов `nextCommand` |
| ЧТЗ-02-R14 | Обработка разорванного блока данных без порчи состояния других соединений |
| ЧТЗ-02-R15 | Устаревший аргумент `<time>` у `delete` принимается и игнорируется как известное отличие |
| ЧТЗ-02-R16 | Возобновляемый писатель ответа по контракту 03 §4.6: `WriteStatus`, продолжение после `OP_WRITE` по `remainingCapacity`, один вызов `encode` на команду, ограничение размера части |
| ЧТЗ-02-R17 | Декодер возвращает одну команду за вызов (`nextCommand`) и `null` при недостатке данных |
| ЧТЗ-02-R18 | Полная ёмкость приёмника ответа не меньше 2 байт; `protocol.maxChunkBytes` не меньше 2; при `remainingCapacity()==0` — `IN_PROGRESS` без записи; при `==1` разрешён один обычный байт, но не половина `\r\n`; ожидание дренирования/наполнения без spin; постоянная ёмкость 1 и предел части 1 недопустимы (ADR-015) |
| ЧТЗ-02-R19 | `CacheCapacityException` из `touch`/`gat`/`gats` даёт `SERVER_ERROR out of memory storing object`; `noreply` подавляет ответ только у `touch`, `gat`/`gats` всегда отвечают, а `noreply` в них — обычный ключ; состояние и срок записи не меняются; удержания освобождаются (ADR-013) |
| ЧТЗ-02-R20 | Чтение использует один заранее допущенный снимок всей команды, один курсор значения без полной копии; первая позиция каждого уникального ключа определяет порядок. Отказ допуска до первого байта даёт известный SERVER_ERROR без частичного VALUE; после начала только backpressure буфера, не поздний отказ допуска. COMPLETE/cancel/disconnect/shutdown идемпотентно закрывают весь снимок (ADR-016) |

**Обработка ошибок.** Ошибки формата возвращают `CLIENT_ERROR` или `ERROR` и не меняют состояние кеша. Внутренние ошибки движка переводятся в `SERVER_ERROR`.

**Запрещено.** Молчаливое проглатывание команд, изменение состояния при синтаксической ошибке, ответы на команды с `noreply` кроме случая нарушения кадрирования.

**DoD.** Компиляция, unit-тесты парсера, полный перечень строк ошибок. **Трассировка.** Т-01, Т-02.

## ЧТЗ-03. Хранилище и распределитель памяти

**Цель.** Хранить записи в памяти, раскладывать по классам размеров, освобождать память и не превышать предел.

**Владелец.** Пакет `ru.octomem.storage`.

**Требования.**

| ID | Требование |
|---|---|
| ЧТЗ-03-R01 | Хеш-таблица со ссылками на записи, устойчивая к коллизиям |
| ЧТЗ-03-R02 | Ключ — произвольные байты, сравнение побайтовое |
| ЧТЗ-03-R03 | Распределитель по классам размеров с шагом роста (по умолчанию 1,25) |
| ЧТЗ-03-R04 | Страницы фиксированного размера (по умолчанию 1 МиБ) |
| ЧТЗ-03-R05 | Учёт общего и занятого объёма, статистика по классам |
| ЧТЗ-03-R06 | Освобождение памяти при удалении и просрочке |
| ЧТЗ-03-R07 | Возврат `OUT_OF_MEMORY` при невозможности разместить запись после вытеснения |
| ЧТЗ-03-R08 | Запись целиком хранится вне кучи; backend FFM или direct ByteBuffer фиксируется по docs/03 и java-platform.md до T-009 |
| ЧТЗ-03-R09 | Ограничение размера записи `item.maxSize` (ключ, служебные поля, значение) |
| ЧТЗ-03-R10 | Захват и освобождение ссылок на запись без обращения к освобождённой памяти |
| ЧТЗ-03-R11 | Расширение хеш-таблицы при росте числа записей |
| ЧТЗ-03-R12 | Отсутствие утечек прямых буферов при любых путях ошибок |
| ЧТЗ-03-R13 | Под удержанием (`ItemLease`) блок не освобождается и не переиспользуется при удалении, замене, просрочке и вытеснении |
| ЧТЗ-03-R14 | Опубликованная версия неизменяема: ключ, флаги, срок, `cas` и значение не меняются на месте; изменение — allocate → publish → retire; старая версия освобождается после нуля удержаний; LRU/refcount — отдельное изменяемое состояние. При отказе выделения старое значение сохраняется, кроме инвалидации SET по docs/04, коррекция 0.4; удержанные версии при этом не повреждаются (ADR-013/019) |
| ЧТЗ-03-R15 | Все native-страницы и резервы будущих страниц входят в `memory.limit`; live/retained/retired/reserved-блоки учтены без двойного счёта. Retired освобождается только при refs0; записи резервируют замену атомарно либо OOM без частичного состояния и ожидания сокета (ADR-016) |

**Структуры.** Заголовок неизменяемой версии: ключ, флаги, срок, версия, длина, класс размера. Значение — часть того же выделенного блока; отдельный буфер под значение не создаётся. Позиция в LRU и счётчик удержаний — отдельное изменяемое служебное состояние, не входящее в версию ([ADR-013](adr/ADR-013-immutable-published-item-version.md)).

**Обработка ошибок.** Ошибка выделения приводит к вытеснению, затем к `OUT_OF_MEMORY`. Двойное освобождение и обращение после освобождения запрещены и проверяются тестами.

**DoD.** Компиляция, unit-тесты распределителя, локальная проверка отсутствия роста прямых буферов. **Трассировка.** Т-03, Т-05.

## ЧТЗ-04. Срок жизни и вытеснение

**Цель.** Просроченные записи не отдаются, память под ними освобождается, при нехватке вытесняются давно неиспользуемые записи.

**Владелец.** Пакеты `ru.octomem.expiry`, `ru.octomem.eviction`.

**Требования.**

| ID | Требование |
|---|---|
| ЧТЗ-04-R01 | Ленивая проверка срока при чтении и записи |
| ЧТЗ-04-R02 | Фоновый поток активной очистки просроченных записей |
| ЧТЗ-04-R03 | `flush_all` с задержкой и без задержки по правилам 04 |
| ЧТЗ-04-R04 | Вытеснение по политике LRU при нехватке памяти |
| ЧТЗ-04-R05 | Настройка политики (по умолчанию `lru`) |
| ЧТЗ-04-R06 | Отметка активности записи без дорогой блокировки на каждом чтении |
| ЧТЗ-04-R07 | Счётчики `reclaimed`, `expired_unfetched`, `evicted_unfetched` |
| ЧТЗ-04-R08 | Отдельные очереди LRU по классам размеров |
| ЧТЗ-04-R09 | Проверка времени только через `Clock` для детерминированных тестов |
| ЧТЗ-04-R10 | Фоновые потоки не блокируют обработку соединений |
| ЧТЗ-04-R11 | Период фоновой очистки задаётся настройкой `expiry.reclaimIntervalSeconds` |

**Обработка ошибок.** Ошибка фонового потока не завершает процесс и пишется в журнал. Запись, просроченная на capturedClock снимка, не возвращается; истечение после захвата не отменяет попадание уже принятого снимка. Expiry/eviction соблюдают segment locks и границу атомарности ADR-016, не освобождают pinned-блок.

**DoD.** Компиляция, unit-тесты времени и LRU, локальная проверка отсутствия возврата просроченных значений. **Трассировка.** Т-02, Т-04.

## ЧТЗ-05. CAS и атомарность

**Цель.** Обеспечить уникальные версии записей и атомарные изменения.

**Владелец.** `ru.octomem.engine`.

**Требования.**

| ID | Требование |
|---|---|
| ЧТЗ-05-R01 | Глобальный счётчик новых wire-CAS в пределах процесса; перенос прежнего CAS в новую TTL-only версию не считается выдачей нового токена и не доказывает тождества физических блоков |
| ЧТЗ-05-R02 | Storage-операции и `incr`/`decr` обновляют CAS при успешном изменении; успешные `touch`/`gat`/`gats`, изменяющие только TTL, сохраняют CAS по эталону 1.6.45. Внутренняя версия и wire-CAS различаются |
| ЧТЗ-05-R03 | `gets` и `gats` возвращают версию |
| ЧТЗ-05-R04 | `cas` возвращает `STORED`, `EXISTS`, `NOT_FOUND` по правилам |
| ЧТЗ-05-R05 | `incr` и `decr` атомарны; `incr` заворачивается по модулю `2^64`, `decr` при вычитании больше значения даёт `0` |
| ЧТЗ-05-R06 | Одиночная команда атомарна относительно других соединений |
| ЧТЗ-05-R07 | Отсутствие взаимных блокировок при конкурентных операциях |
| ЧТЗ-05-R08 | Неверное числовое значение в `incr`/`decr` даёт `CLIENT_ERROR` |
| ЧТЗ-05-R09 | Обновление записи не оставляет промежуточного состояния, видимого читателю |
| ЧТЗ-05-R10 | Токен `cas` разбирается и выводится как беззнаковое 64-битное число |
| ЧТЗ-05-R11 | Обновление не изменяет опубликованную версию на месте: `incr`, `decr`, `append`, `prepend`, `touch` публикуют новую версию; при отказе выделения старое значение сохраняется (ADR-013) |
| ЧТЗ-05-R12 | Восстановимый отказ выделения при `touch` и `getAndTouch`/`gat`/`gats` сигнализируется проверяемым `CacheCapacityException`, а не `false` или промахом; запись, срок и `cas` не меняются, удержания освобождаются; движок отображает в `SERVER_ERROR out of memory storing object` (ADR-013) |
| ЧТЗ-05-R13 | Multi-`gat`/`gats` готовит все версии и резервы до публикации под всеми locks; отказ освобождает неопубликованное без изменения исходных значений/TTL/CAS любого ключа. Дубли обновляются один раз; R-04 закрыт как DESIGN finding принятого ADR-016, реализация проверяется отдельно |
| ЧТЗ-05-R14 | Вся команда чтения захватывается под уникальными segment locks по возрастанию индекса с одним capturedClock и согласованным flush; pin всех уникальных попаданий до unlock, промахи фиксированы. Сеть/callbacks под locks запрещены; FR-40 не сужается до ключа |
| ЧТЗ-05-R15 | Допуск метаданных до захвата/первого байта: cap `min(floor(memory.limit / 16), 16 MiB)`, checked плата `512 + 512 * N` за все позиции. Ровно шесть плоских массивов и модель 271N payload/384 headers/128 wrapper-scratch по ADR-016 F3, ключ≤250, in-place iterative heapsort без perkey объектов/роста/массивов по общему числу сегментов; internal key view без defensive copy, layout проверяется на JDK25, не RSS-гарантия |
| ЧТЗ-05-R16 | Sorted segment locks → allocator mutex → LRU metadata; под набором не брать новые segment locks/eviction. Eviction preflight отдельно после unlock с исключением целевых ключей, затем полный повторный захват и новый Clock; никаких I/O/queue waits под locks, полный rollback сохранён (ADR-016 §5) |

**Обработка ошибок.** Несовпадение версии не меняет запись и возвращает `EXISTS`. Отсутствие ключа возвращает `NOT_FOUND`.

**DoD.** Компиляция, unit-тесты версий, локальная проверка отсутствия гонок под нагрузкой. **Трассировка.** Т-04.

## ЧТЗ-08. Безопасность

**Цель.** Не создавать угроз по умолчанию и корректно обрабатывать недоверенный ввод.

**Владелец.** Все пакеты; ответственный — архитектор безопасности.

**Требования.**

| ID | Требование |

| ЧТЗ-08-R02 | Отсутствие исходящих сетевых соединений |
| ЧТЗ-08-R03 | Отсутствие телеметрии, активации и обязательных внешних сервисов |

| ЧТЗ-08-R06 | Понятное предупреждение в журнале при привязке к непубличному, но широкому адресу |

| ЧТЗ-08-R09 | Зависимости только свободные, с проверенными лицензиями |

**DoD.** Компиляция, локальная проверка отсутствия сетевых соединений, перечень ограничений. **Трассировка.** Т-06.
