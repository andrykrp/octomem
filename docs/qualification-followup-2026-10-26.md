Дата отчёта:26.10.2026 по локальному календарю; raw timestamps — UTC25.10.2026. Это продолжение инженерной проверки, не выпуск и не заключение для реестра.

## Git

По явному поручению владельца опубликован первоначальный коммит `ba02d642f9565c167cf239a665cfedf8efa61332` в <https://github.com/andrykrp/octomem>, ветка main. Remote до публикации не содержал refs; чужая история не перезаписывалась. Состав прошёл независимое ревью:383текстовых файла, без локальных JDK, эталонного кода, сертификатов, дампов, сырых архивов и операторских параметров доступа. Hash-pinned файлы сохранены побайтово, `mvnw` имеет executable bit. Подробности ограничения нового checkout — [source-publication.md](source-publication.md).

GitHub-публикация разрешена владельцем, но сама по себе **не доказывает REG-08/09**. Правовая применимость зарубежного зеркала и контролируемый российский контур исходников/сборки/распространения остаются отдельными пунктами проверки. Лицензия проекта, правообладатель, договоры, выплаты и персонал поддержки не выдумывались.

## Java-клиент

Использован настоящий `net.spy:spymemcached:2.12.3` из официального Maven Central, Apache2.0 по опубликованному POM. SHA-256 тестового JAR:
`133092565F8308B9BCBFCE83909D11F505D4094B856EAD24E299AC93679BB4E2`.
Библиотека загружена только в изолированный тестовый classpath; зависимости сервера не изменились.

Проверены set/get,gets/CAS, отказ staleCAS,multi-get,increment/decrement,miss, закрытие первого клиента и чтение сохранённых данных через **новый экземпляр** клиента, delete. Это не проверка автоматического failover/recovery после рестарта. JavaTLS/SASL не заявлены этим пилотом; PythonTLS/SASL проверялись отдельно. Первый неудачный запуск harness из-за асинхронной готовности соединения сохранён; исправлен initial-observer barrier, не ожидания команд и не retry.

2. Подготовить переносимый квалификационный контур для чистого checkout: полный verify сейчас требует отдельно сохранённых reference/evidence inputs, а не только Git-файлов.

4. Выполнить TEST-05 M1/M2 по заранее зафиксированной методике и TEST-09 длительный прогон на одном кандидате. Совместное выполнение с фоновыми задачами или короткий smoke не заменяет требуемые пары/72часа.
5. Квалифицировать точные доверенные ОС+JDK+архитектуры и подтвердить юридические REG-пункты документами владельца/юриста. Публичные исследования и GitHub-коммит не являются такими документами.
