# octomem: продуктовый бриф

Версия 0.1 от 14.09.2026.

## 1. Что это

`octomem` — сервер оперативного кеширования в оперативной памяти, совместимый с протоколом Memcached. Приложение подключается к нему существующей клиентской библиотекой Memcached и продолжает работать без изменения логики.

```text
Приложение (клиент Memcached) -> адрес octomem -> значение по ключу
```

Данные живут в памяти и не сохраняются на диск. Это кеш, а не источник истины: при перезапуске содержимое теряется, а приложение восстанавливает данные из основной базы.

## 2. Проблема и ценность

**Проблема.** Компаниям, которые обязаны или хотят использовать отечественное ПО, нужна замена Memcached для уже работающих приложений, без переписывания кода и без тяжёлой кластерной платформы.

**Решение.** Совместимый по протоколу сервер с собственным ядром, простой установкой, предсказуемым потреблением памяти и бесплатной базовой лицензией.

**Ценность:**

- Плавный переход: меняется адрес, а не код.
- Малое и предсказуемое потребление памяти.
- Простая эксплуатация без обязательного кластера и постоянного хранилища.
- Отсутствие обязательных платных компонентов.

## 4. Цели выпуска 1.0

- **G1.** Совместимость с обязательным профилем текстового протокола Memcached, подтверждённая конформными тестами и реальными клиентами.
- **G2.** Корректная работа под нагрузкой: параллельные соединения, конвейер запросов, атомарные `incr`, `decr` и `cas`.
- **G3.** Предсказуемое ограничение памяти с вытеснением и сроком жизни ключей.
- **G4.** Диагностика через команду `stats` и журналирование.
- **G5.** Воспроизводимая сборка и поставка без обязательных платных компонентов.
- **G6.** Комплект доказательств для приёмки и подготовки к реестру.

## 5. Не-цели

- **NG1.** Постоянное хранение данных и восстановление после перезапуска.
- **NG2.** Кластер, репликация, шардирование, автоматический отказоустойчивый переход.
- **NG3.** Совместимость с Redis и его командами.
- **NG4.** Бинарный протокол Memcached и мета-команды в выпуске 1.0.
- **NG5.** Встроенная аутентификация и шифрование канала в выпуске 1.0.
- **NG6.** Графический интерфейс.
- **NG7.** Гарантии «ровно один раз» для распределённых блокировок.
- **NG8.** Работа с данными как с источником истины.

## 7. Ограничения

- **Язык:** Java, основная OpenJDK 25, байткод 25; 21 только резерв после отдельного решения и испытаний. Без Java 17 и preview API. См. [платформу](java-platform.md).
- **Транспорт:** собственный цикл на `java.nio`, без тяжёлых фреймворков.
- **Память:** данные только в оперативной памяти, объём ограничивается настройкой.
- **Развёртывание:** один процесс, локальная установка.
- **Лицензии:** только свободные, обязательные runtime-компоненты бесплатны.
- **Инфраструктура:** сборка, хранение исходников и распространение — в России.

## 9. Ключевые риски

| Риск | Влияние | Снижение |
|---|---|---|
| Несовпадение поведения с эталоном в редких случаях | Приложение ломается при переходе | Конформные тесты, перечень известных отличий, пилоты |
| Гонки и ошибки в неблокирующем транспорте | Падения и зависания | Отдельное ЧТЗ, тесты конкуренции, простые контракты |

| Класс в реестре и требования доверенных ОС | Задержка регистрации | Проверка класса в 09 до подачи |

## 10. Глоссарий

- **Ключ** — идентификатор записи, до 250 байт, без пробелов и управляющих символов.
- **Значение** — произвольные байты; входит в настраиваемый предел размера записи.
- **Флаги** — целое число, непрозрачное для сервера, возвращается клиенту.
- **CAS** — уникальный номер версии записи для условного обновления.
- **TTL, `exptime`** — срок жизни записи.
- **Вытеснение** — удаление записей при исчерпании памяти.
- **`flush_all`** — инвалидация всех записей.
- **Эталон** — выбранная версия оригинального Memcached для сравнения.
- **Конформность** — соответствие обязательному профилю протокола.
