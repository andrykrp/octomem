# OpenJDK и производительность

Актуальное решение владельца от 14.09.2026: основная платформа **OpenJDK 25**, сборка с `--release 25`, без preview/incubator и внутренних API. Java 17 исключена. OpenJDK 21 только резервный план при подтверждённом блокере 25, не обязательная платформа и не ограничение основного кода. Используются исключительно свободные сборки OpenJDK; точные поставщики, patch-версии и SHA-256 фиксируются. Oracle JDK и proprietary runtime не являются платформами проекта.

## Выбор версии

[JDK 25](https://openjdk.org/projects/jdk/25/) вышла 16.09.2025 и относится к LTS у большинства поставщиков. Срок и условия обновлений определяет поставщик конкретной сборки, не один номер версии.

25 выбрана основной, но ускорение не гарантировано: измеряются throughput, p99, CPU, RSS, аллокации и GC. JAR с байткодом 25 не запускается на 21. Резерв требует отдельного ADR, адаптации исходников/API, отдельного артефакта и повторных испытаний; автоматического переключения JVM нет. Не вести две реализации заранее и не маркировать 21 как поддержанную без доказательств.

Стабильный FFM API появился в JDK 22 ([JEP 454](https://openjdk.org/jeps/454)) и доступен в основной 25. Для allocator допускаются MemorySegment/Arena без внешней native-библиотеки; выбор относительно direct ByteBuffer фиксируется до T-009 по прототипу и контракту владения. Закрытие arena не заменяет lease записи, защиту от изменения и порядок остановки конкурентных читателей. Для доступа разных event loops нельзя использовать confined arena без соответствующего ограничения владения.

Освобождение блока в странице не равно возврату страницы ОС. Direct ByteBuffer не даёт стандартного детерминированного освобождения; обходы через Unsafe/reflective Cleaner запрещены. Arena позволяет управлять сроком жизни памяти через стандартный API, но её применение и производительность требуют тестов. FFM 21 preview не является прозрачной заменой API 25; резерв не использует preview как обход совместимости.

## Библиотеки

В runtime сервера ноль сторонних Java/native-библиотек, только стандартная библиотека OpenJDK. Без Spring Boot, Netty, DI, ORM, Lombok и внешнего logging backend. Не копировать код зависимостей ради формального нуля. Исключение требует обоснования и разрешения владельца.

Maven Wrapper, плагины, JUnit и при необходимости OpenJDK JMH/jcstress допустимы для сборки, тестов и измерений. Версии и транзитивные зависимости фиксируются, лицензии и уязвимости проверяются; в серверный JAR они не входят. T-001 проверяет runtime dependency tree и содержимое JAR. OpenJDK остаётся явно указанной платформой, а не скрывается формулировкой «ноль зависимостей».

## Эффективность

1. Сначала корректность и конкурентная безопасность, затем оптимизация по профилю. Сохранить NIO event loop, backpressure и ограничение работы одного соединения за проход. Virtual threads не считать автоматическим ускорением CPU.
2. Избегать лишних String, regex, boxing и копирований в горячем пути. Не обещать zero-copy; измерять фактические копии и аллокации.
3. Ограничить буферы и очереди. Раздельно учитывать heap, direct memory, входные команды, подготовленные ответы, удержанные записи и RSS. Лимит кеша не равен лимиту процесса.
4. Определить порядок блокировок, владение и неизменяемость удержанных версий. Не вводить lock-free алгоритмы и глобальные пулы без измеренной необходимости.
5. Использовать JFR; сравнивать GC и JVM flags при одинаковых бюджетах CPU/памяти. Не объявлять какой-либо GC универсально лучшим.
6. Микробенчмарки выполнять с прогревом, отдельными forks и защитой от dead-code elimination. JMH не заменяет сетевые прогоны: фиксировать offered load, ошибки, распределение размеров/ключей, учитывать coordinated omission, сохранять сырые данные.

Цели M1–M3 не ослабляются. Обязательные наборы выполняются на OpenJDK 25 на каждой заявленной платформе. Резерв 21 проверяется только после его отдельного введения. Для реестра проверяется точная комбинация ОС/CPU/OpenJDK/артефакт по [REG-11](ref-registry-research.md); нехватка подходящей сборки 25 на доверенной ОС является риском, не разрешением объявить 21 проверенной.
