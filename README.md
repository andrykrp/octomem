# octomem.octocode.tech

Проект `octomem` — самостоятельный сервер оперативного кеширования, совместимый с протоколом Memcached. Приложение подключается к нему существующей клиентской библиотекой Memcached: меняется адрес сервера, а не код приложения.

Репозиторий проекта: <https://github.com/andrykrp/octomem>. Локальное имя каталога — `octomem.octocode.tech`; права на домен и товарный знак не проверены. [Состав публикации и локальные доказательства](docs/source-publication.md).

## 2. Структура

| Каталог | Назначение | Правило изменения |
|---|---|---|
| `docs/` | Общие документы проекта и источник истины по требованиям | Меняет только владелец документа; контракт протокола — через [docs/04](docs/04-protocol-compatibility-specification.md) |
| `tasks/` | Задачи реализации с критериями приёмки | По одной задаче на файл; новая задача добавляется в реестр [tasks/00-index.md](tasks/00-index.md) |

| `ui/` | Задачи по интерфейсу пользователя. В этом проекте **пусто**: графического интерфейса в 1.0 нет | Не заполнять без изменения области выпуска |
| `design/` | Задачи дизайна: интерфейс командной строки, сообщения, схема конфигурации, структура справки | Согласуется с docs/02 и docs/04 |

## 3. Методика взаимодействия со структурой

Проектные требования заданы в [руководстве разработки](docs/development.md). Координация автономной работы выполняется глобальным `/auto`. Кратко:

1. **Документы первичны.** Сначала меняется требование в `docs/`, затем задача в `tasks/`, затем код. Обратный порядок запрещён: нельзя «подогнать» документ под уже написанный код без явного решения ведущего.
2. **Задача — единица работы.** Каждый файл в `tasks/` самодостаточен: цель, зависимости, входы, результаты, критерии приёмки, роли. Исполнитель берёт одну задачу и не трогает чужие.
3. **Независимая проверка.** Реализацию принимает контролёр, не писавший код. Тесты обязательного профиля пишет отдельный агент.
4. **Критерии не ослабляются.** Изменять ожидаемые результаты, удалять тесты или сужать профиль ради зелёного результата запрещено. Изменение критерия — решение ведущего с записью в журнал решений.
5. **Испытания релиза отдельно.** Задачи в `tests/` запускаются на зафиксированной сборке перед выпуском и не заменяются отчётами разработчиков.
6. **Пустая ветка — это нормально.** Отсутствие задач в `ui/` означает «в выпуске нет интерфейса», а не «забыли заполнить».

## 4. Автономная работа

Используется глобальная команда `/auto` установленной конфигурации OpenCode. Она определяет координацию, модели, восстановление и независимое ревью. Локальное описание `octocode` удалено как дублирующее и не реализованное.

Дополнительные требования именно этого проекта: независимое авторство обязательных релизных тестов и все финальные испытания на одной сборке. Они сохранены в [docs/development.md](docs/development.md), вместе с обоснованием удаления. Настройки и внутренний механизм `/auto` в проект не копируются.

## 5. С чего начать

1. Прочитать [ревью](docs/review-2026-09-14.md) и [правила разработки](docs/development.md).
2. Открыть [docs/00-index.md](docs/00-index.md) и [tasks/00-index.md](tasks/00-index.md). Карточки каталогов, а не исторические `ЗАД-*`, задают текущую очередь.
3. Сверить текущую [матрицу доказательств](tests/reports/release/EVIDENCE-MATRIX.md) с решениями владельца; старые даты и кандидаты не считать текущей приёмкой.
4. Продолжить очередь AUTO-01…AUTO-10 из [актуального плана](docs/release/11-owner-decisions-and-next-work.md), не начинать существующую реализацию заново с T-001.
5. Для автономного исполнения использовать глобальный `/auto` с указанием цели и правил из `docs/development.md`. Он не гарантирует фоновую работу после закрытия сессии.

## 6. Границы проекта

В текущую реализацию входят classic text, binary и meta Memcached, ограниченная память и вытеснение, TTL, CAS, счётчики и статистика, CLI/конфигурация, SASL PLAIN/text auth/TLS и локальные Unix/UDP транспорты. Это состав реализации, не объявление приёмки выпуска1.0. Точные ограничения — [в профиле совместимости](docs/memcached-protocols-and-security.md).

Вне текущей области: постоянное хранение на диске, кластер, Redis-команды и графический интерфейс. Старые исключения binary/meta/auth из исходного плана1.0 были отменены прямым поручением владельца; исторические [docs/01](docs/01-product-brief.md) и [docs/02](docs/02-general-technical-specification.md) не отменяют последующие требованияT-019.

## 7. Ограничения

- Основная платформа OpenJDK 25, --release 25; 21 только резервный план, не совместимость основного JAR. Java 17 исключена. Ноль сторонних runtime-библиотек. См. [платформу](docs/java-platform.md).
- Данные только в памяти; это кеш, а не источник истины.
- Совместимость подтверждается тестами против зафиксированной версии эталонного Memcached; файл манифеста совместимости создаётся в первой задаче.
- Регистрация в реестре не гарантируется и не входит в инженерную готовность. Реестровый чек-лист — в [docs/09](docs/09-acceptance-and-registry-readiness.md).

Включение готового продукта в реестр является целью владельца. Ограничения REG-01…REG-14 находятся в [реестровой матрице](docs/ref-registry-research.md), а актуальная условная рекомендация и шлюзы для трёх российских ОС -- в [отдельном исследовании](docs/ref-trusted-os-selection.md). До передачи исходников внешним моделям и выбора CI проверить российское размещение, права и договоры. Для предполагаемых классов СУБД и серверного/связующего ПО требование двух доверенных ОС применяется с 01.01.2027; доказательства планируются заранее.
