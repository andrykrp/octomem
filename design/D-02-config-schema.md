# D-02. Схема конфигурации

**Цель.** Определить человекочитаемую схему файла конфигурации.

**Зависит от.** D-01.

**Входы.** docs/03 §8.

**Результаты.**
- Формат файла и правила комментариев.
- Таблица ключей: имя, тип, единицы, значение по умолчанию, допустимые границы.
- Суффиксы размеров и их разбор.
- Границы: `protocol.maxChunkBytes` не меньше 2 байт (значение по умолчанию `64k` не меняется); полная ёмкость приёмника ответа не меньше 2 байт (ADR-015).
- Пример полного файла с комментариями на русском языке.
- Формулировки ошибок проверки конфигурации.

**Критерии приёмки.**
1. Каждый ключ docs/03 §8 описан и имеет значение по умолчанию.
2. Пример полного файла приведён и синтаксически согласован с набором ключей. Исполняемая проверка примера выполняется в T-002 после реализации валидатора.
3. Секреты не входят в пример и не выводятся при проверке.
4. Формулировки ошибок для ошибочных значений заданы с именем ключа.
5. Для `protocol.maxChunkBytes` задана нижняя граница 2 байта (значение по умолчанию не меняется).

**Проверка.** Ревью ведущим и контролёром; синтаксическая согласованность примера с набором ключей проверяется вручную. Исполняемая проверка примера выполняется в T-002 после появления валидатора.

**Роли.** Исполнитель — дешёвый; контролёр — сильный.

**Вне области.** Изменение набора ключей.

**Ограничения.** Схема не добавляет и не переименовывает ключи docs/03 §8.
