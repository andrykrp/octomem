# Конфигурация и CLI octomem

Результаты D-01, D-02, D-03 и D-04 для T-002. Набор из 14 ключей и значения по умолчанию взяты из [архитектуры, раздел 8](../docs/03-architecture-specification.md#8-конфигурация). Конкретный интерфейс согласован координатором в сообщениях `msg_d18930e3e673` и `msg_701b4d44af5b`.

## D-01. Команды

```text
java -jar octomem-1.0.0.jar [--config ПУТЬ] [--ключ=значение]
java -jar octomem-1.0.0.jar --check-config [--config ПУТЬ] [--ключ=значение]
java -jar octomem-1.0.0.jar --help
java -jar octomem-1.0.0.jar --version
```

Все имена после `--` совпадают с ключами ниже, включая регистр. Алиасов ключей нет. Путь передаётся отдельным аргументом `--config ПУТЬ` или после знака равенства `--config=ПУТЬ`; при пробелах используется экранирование оболочки. Повторы запрещены, в том числе сочетание обеих форм. Для пути, начинающегося с `--`, используйте форму со знаком равенства либо явный относительный или абсолютный путь. Позиционные аргументы и одиночный `--` запрещены.

Приоритет: CLI > файл > значения по умолчанию. Без `--config` никакой файл не ищется и не читается. Повторы ключей внутри CLI или файла запрещены; ключ одновременно в файле и CLI допустим. Повторы режимов и `--config` запрещены. `--help` и `--version` работают отдельно, без файла, переопределений и других режимов. Порядок параметров проверки произвольный.

Проверка не открывает порт, не выполняет DNS-запросов, не создаёт рабочие потоки и не выделяет память кеша. Она не проверяет доступность адреса, занятость порта или фактическую возможность выделить заданный бюджет. Нормальный запуск после успешной валидации пока возвращает ошибку: транспорт вне T-002. Это не работающий сервер и не имитация успешного запуска.

## D-02. Файл

Формат: UTF-8, одна пара `ключ=значение` на строку. Рекомендуемое имя поставки `octomem.conf`; расширение не влияет на загрузку. [Полный пример](config-example.properties) имеет расширение `.properties` по заданию и проходит тем же загрузчиком. Он показывает все 14 ключей; `transport.workers` оставлен комментарием, чтобы не подменить вычисляемое значение числом для конкретной машины. После загрузки пример даёт все значения по умолчанию.

- Разделитель только `=`. Пробелы ASCII и табуляции на краях строки, ключа и значения удаляются. Внутри значения пробелы не разрешены грамматикой соответствующего типа. CLI значения не обрезает.
- Пустые строки и строки с первым непробельным символом `#` или `!` игнорируются. Комментариев после значения нет.
- Допустимы LF и CRLF. Отдельный CR запрещён. Последняя строка может не иметь перевода строки.
- BOM допустим только первым символом файла. Повторный или встроенный BOM запрещён, включая комментарии.
- Нет кавычек, escape-последовательностей, продолжений строк, интерполяции `${...}`, переменных окружения или включения файлов. Обратная косая черта в значении запрещена, никогда не разворачивается и не открывает файл.
- Неизвестный ключ, повтор ключа и неверный синтаксис отвергаются до слияния источников. Значение файла должно быть непустым после удаления краевых ASCII-пробелов и табуляций: `listen.port=` и значение только из пробелов или табуляций являются ошибками синтаксиса даже при переопределении через CLI. Тип и диапазон проверяются после слияния: допустимый CLI может заменить непустое синтаксически допустимое, но неверное числовое значение известного ключа файла; он не может скрыть нарушение синтаксиса, неизвестный ключ или повтор.
- Защитные пределы парсера: файл не более 1 048 576 байт, физическая строка не более 8192 UTF-16 единиц без BOM и терминатора. Пределы действуют и на комментарии. Это внутренние ограничения формата, не новые ключи сервера.

Числа содержат только ASCII `0`..`9`, ведущие нули допустимы. Знаки, дроби, экспоненты, группировка, не-ASCII цифры запрещены. Для размеров допустим один суффикс `k/K`, `m/M`, `g/G` с двоичными множителями 1024, 1048576, 1073741824. Например, `00012K` даёт 12288 байт. Проверки выполняются до переполнения при накоплении числа и умножении. Нулевые размеры запрещены. Суффиксы не применяются к портам, счётчикам или секундам.

| Ключ | Тип и единицы | По умолчанию | Границы |
|---|---|---|---|
| `listen.address` | Числовой IPv4/IPv6 | `127.0.0.1` | IPv4: ровно четыре десятичных октета из 1..3 ASCII-цифр, каждый 0..255, разделённых точками; сокращённые и шестнадцатеричные формы запрещены. IPv6: литерал по OpenJDK `InetAddress.ofLiteral`, без скобок и зоны `%`; имена хостов не поддерживаются |
| `listen.port` | Целое, порт TCP | `11211` | 1..65535 |
| `memory.limit` | Размер, байты, `long` | `64m` | 1..9223372036854775807 |
| `item.maxSize` | Размер полной записи, байты, `int` | `1m` | 1..2147483647 и не больше `memory.limit` |
| `connections.max` | Целое, соединения, `int` | `1024` | 1..2147483647 |
| `transport.workers` | Целое, рабочие потоки, `int` | `2 × CPU`, минимум 2 | Явное значение 1..2147483647; CPU берётся из `Runtime.availableProcessors()` |
| `eviction.policy` | Перечисление | `lru` | Только точное `lru` |
| `expiry.reclaimIntervalSeconds` | Целое, секунды, `long` | `1` | 1..9223372036 |
| `protocol.maxLineBytes` | Размер, байты, `int` | `8192` | 1..2147483647 |
| `protocol.maxChunkBytes` | Размер, байты, `int` | `64k` | 2..2147483647 |
| `connections.pendingWriteBytes` | Размер, байты, `int` | `8m` | 2..2147483647 |
| `connections.maxInflightCommands` | Целое, команды, `int` | `16` | 1..2147483647 |
| `connections.idleTimeoutSeconds` | Целое, секунды, `long` | `0` | 0..9223372036; ноль отключает тайм-аут |
| `log.level` | Перечисление | `info` | `error`, `warn`, `info`, `debug`, ASCII-регистр не важен |

Верхняя граница секунд позволяет безопасное умножение на 1 000 000 000 при переводе в наносекунды. Границы `int` отражают контракты длины записей и буферов, а не гарантию наличия такого количества памяти. Размер записи включает ключ, служебные поля, значение и выравнивание. Ограничение `memory.limit` относится к кешу, не к heap или RSS процесса.

Полная ёмкость приёмника ответа должна быть не менее 2 байт; поэтому `connections.pendingWriteBytes` тоже не меньше 2. Максимальная часть может быть больше очереди: транспорт ограничит фактическую часть доступным местом. Не требуется `item.maxSize <= pendingWriteBytes`: большие ответы передаются частями. Не требуется бюджет всех соединений меньше бюджета кеша: это разные категории памяти. Их совокупный размер и накладные расходы JVM проверяет эксплуатация.

### Контракт Java

`ConfigLoader.load(Path, Map<String,String>)` статический, возвращает `ServerConfig`, выбрасывает проверяемый `ConfigException`. `null` вместо пути означает отсутствие файла; `null` вместо карты или значения считается ошибкой конфигурации. `ConfigLoader.defaults()` возвращает неизменяемую карту канонических значений по умолчанию: размеры записаны десятичным числом байтов без суффиксов. Она равна `ConfigLoader.load(null, Map.of()).values()`. Карта результата `ServerConfig.values()` неизменяема и содержит 14 ключей: числа и размеры канонизированы в десятичную запись без суффиксов, уровень журнала в нижний регистр; адрес остаётся проверенным литералом. Входные карты не сохраняются и не меняются.

Типизированные методы: `listenAddress():String`, `listenPort():int`, `memoryLimit():long`, `itemMaxSize():int`, `connectionsMax():int`, `transportWorkers():int`, `evictionPolicy():String`, `expiryReclaimIntervalSeconds():long`, `protocolMaxLineBytes():int`, `protocolMaxChunkBytes():int`, `connectionsPendingWriteBytes():int`, `connectionsMaxInflightCommands():int`, `connectionsIdleTimeoutSeconds():long`, `logLevel():String`. Создать непроверенную конфигурацию через публичный конструктор нельзя. Пакет `config` зависит только от JDK, не от `util`.

## D-03. Вывод

`Main.run(String[], PrintStream, PrintStream)` возвращает код, не завершает JVM. `main` передаёт код в `System.exit`. Пользовательские сообщения русские; идентификаторы продукта, ключи и строки протокола не переводятся.

| Событие | Поток | Код | Сообщение |
|---|---|---|---|
| Версия | stdout | 0 | `octomem 1.0.0` |
| Справка | stdout | 0 | Структура D-04 ниже |
| Успешная проверка | stdout | 0 | `Конфигурация корректна. Сервер не запущен.` |
| Ошибка аргументов | stderr | 2 | `Ошибка аргументов. Используйте --help; каждый параметр задаётся только один раз.` |
| Ошибка значения | stderr | 2 | `Ошибка конфигурации <известный ключ>: <причина без значения>.` |
| Неизвестный ключ файла | stderr | 2 | `Неизвестный ключ конфигурации, строка <номер>. См. --help.` |
| Повтор известного ключа | stderr | 2 | `Повтор ключа <ключ>, строка <номер>.` |
| Неверная строка | stderr | 2 | `Неверный формат строки конфигурации: <номер>. Ожидается ключ=значение.` |
| Ошибка чтения или UTF-8 | stderr | 2 | `Не удалось прочитать файл конфигурации. Проверьте путь, права доступа и кодировку UTF-8.` |
| Слишком большой файл | stderr | 2 | `Файл конфигурации превышает допустимый объём.` |
| Недоступный запуск | stderr | 1 | `Ошибка запуска: сетевой транспорт пока не реализован. Используйте --check-config.` |
| SIGINT, после реализации транспорта | stderr, журнал | 130 на POSIX | `Сервер остановлен по сигналу.` |
| SIGTERM, после реализации транспорта | stderr, журнал | 143 на POSIX | `Сервер остановлен по сигналу.` |

Коды сигналов проектные: T-002 не устанавливает обработчики, не использует внутренние API сигналов и не заявляет проверку остановки. На Windows код завершения по сигналу определяется JVM и оболочкой и не объявляется равным POSIX. При реализации жизненного цикла нормальные события запуска/остановки идут в журнал с уровнем `info`, предупреждения о широком адресе с `warn`, отказы с `error`; текст одного события в консоли и журнале должен совпадать. Формат будущего запуска: `Сервер запущен.` Только после фактического открытия слушателя; сейчас такое сообщение не выводится.

Ошибки содержат только доверенные названия ключей, фиксированные причины, границы и номера строк. Неизвестные ключи не повторяются: они могут содержать секрет. Не выводятся сырые аргументы, значения конфигурации, пути, причины I/O-исключений, содержимое кеша или stack trace. `ConfigException` не удерживает исходную причину. Справка показывает только встроенные значения по умолчанию, не пользовательскую конфигурацию. Секретных настроек в выпуске нет; передавать секреты в CLI не следует, поскольку их может видеть сама ОС.

## D-04. Справка

Порядок `--help`: продукт и платформа, синтаксис четырёх команд, сочетания параметров, приоритет источников, формат файла, полный список ключей с умолчаниями, типы/границы, пример проверки, коды возврата, ограничения безопасности, текущий статус транспорта, ссылка на эту схему.
