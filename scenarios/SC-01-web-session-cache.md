# SC-01. Кеш веб-сессий

**Контекст.** Веб-приложение хранит сессии пользователей в общем кеше, чтобы любой экземпляр приложения видел одну сессию.

**Участники.** Приложение (клиент Memcached), octomem, хранилище учётных записей.

**Поток.**
1. После входа приложение создаёт сессию и сохраняет её по ключу вида `session:<id>`.
2. Сервер отвечает `STORED`; приложение отдаёт клиенту идентификатор сессии.
3. При следующих запросах приложение читает сессию по ключу.
4. Активная сессия продлевает срок жизни.
5. При выходе приложение удаляет ключ.

**Команды.** `set`, `get`, `touch`, `delete`.

**Что должно быть верно.**
- Продление срока не теряет данные сессии.
- После истечения ключ не возвращается.
- Перезапуск кеша означает потерю сессий: приложение должно перевести пользователя на повторный вход, а не падать.
- Значение сессии может быть крупным; предел размера записи учитывается.

**Связанные требования.** docs/04, ЧТЗ-02, ЧТЗ-04.

**Открытые вопросы.** Требуется ли сжатие значений на стороне клиента; какой размер сессии типичен.

**Границы.** Общий кеш не даёт гарантий «ровно один раз» и не заменяет распределённую блокировку.
