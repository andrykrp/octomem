# SC-02. Кеш результатов запросов к базе

**Контекст.** Приложение кеширует дорогие результаты запросов к реляционной базе и сбрасывает их при изменении данных.

**Участники.** Приложение, octomem, основная база данных.

**Поток.**
1. Приложение формирует ключ из параметров запроса.
2. При промахе выполняет запрос к базе, сохраняет результат и возвращает его.
3. При попадании отдаёт значение из кеша.
4. При изменении данных приложение удаляет связанные ключи.
5. Для защиты от одновременного пересчёта используется условная запись.

**Команды.** `get`, `set`, `add`, `cas`, `delete`, `flush_all` (осторожно).

**Что должно быть верно.**
- `cas` не позволяет двум процессам одновременно записать значение относительно одной наблюдавшейся версии. Он не гарантирует свежесть вычисленного значения: перед пересчётом приложение обязано прочитать текущую версию.
- Удаление связанных ключей не приводит к возврату устаревших данных.
- `flush_all` инвалидирует весь кеш и применяется осознанно.
- Промахи при холодном кеше не перегружают базу (см. [exp/OPS-03](../exp/OPS-03-recovery-and-warmup.md)).

**Связанные требования.** docs/04, ЧТЗ-05, ЧТЗ-04.

**Открытые вопросы.** Нужен ли шаблон ключей и префиксы; допустимо ли краткое окно устаревания.

**Границы.** Кеш не является источником истины; корректность данных обеспечивает приложение.
