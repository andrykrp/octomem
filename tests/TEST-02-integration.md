# TEST-02. Интеграционные испытания

**Категория.** Интеграционные.

**Цель.** Подтвердить работу с реальными клиентами Memcached и сквозные сценарии без изменения кода приложения.

**Метод.** Пилотные приложения и тестовые программы с реальными клиентскими библиотеками; сервер octomem запущен как отдельный процесс.

**Зависит от.** T-008, T-013, T-015.
**Входы.** docs/06, docs/04.
**Результаты.** Протоколы миграции и отчёты по клиентам.
**Вне области.** Правка приложений-пилотов; допускается только смена адреса сервера.

**Минимум случаев.**
- Клиент Java: чтение, запись, удаление, `cas`, счётчики, `flush_all`.
- Клиент скриптовой экосистемы.
- Клиент, используемый в инфраструктуре заказчика (при наличии).
- Разрыв и переподключение клиента.
- Поведение при истечении срока и вытеснении.
- Мульти-get с крупными значениями при читающем клиенте.
- Сверка `stats` после прогонов.

**Критерии приёмки.**
1. Пилоты проходят свои сценарии без изменения логики приложения; меняется только адрес сервера.
2. Изменение кода приложения означает незачёт пилота как подтверждения замены.
3. Данные и результаты совпадают с ожиданиями приложения.

**Артефакты.** Описание клиентов и версий, протоколы миграции, диффы изменений (только интеграционные).

**Роли.** Тестировщик — сильный; аналитик — при необходимости.

**Ограничения.** Универсальная замена всех клиентских экосистем не заявляется; проверяются перечисленные клиенты.
