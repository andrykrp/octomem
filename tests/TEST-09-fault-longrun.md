# TEST-09. Отказы, ресурсы и длительный прогон

**Категория.** Отказы и ресурсы.

**Цель.** Проверить поведение при исчерпании ресурсов и длительной работе.

**Метод.** Управляемое исчерпание ресурсов, backpressure и 72-часовой прогон.

**Статус 17.09.2026.** 72-часовой прогон остаётся `NOT_RUN` и не входит
в текущую переработку тестовой системы. Короткий soak не заменяет этот критерий.
Запланированы две машины; вторая пока не квалифицирована. Исторические наблюдения
ROSA не доказывают результат новой сборки, правовой доступ или доверенный статус ОС.

**Ожидаемые отказы проверяющей системы.** По [методике версии 2](TESTING-METHOD.md)
потеря работника, неверные байты/порядок ответа, ошибка клиента и незавершённая
очистка дают ненулевой код команды. EOF подтверждается закрытием, не тайм-аутом.
Ресурсные выборки имеют timestamps и разделённые стабильные окна; частый опрос
сам по себе не доказывает устойчивость. Все неудачные попытки сохраняются.
Команды и негативная матрица: [README](README.md).

**Зависит от.** T-006, T-009, T-013, T-015.
**Входы.** docs/06, docs/03.
**Результаты.** Отчёты, снимки ресурсов по часам, найденные дефекты.
**Вне области.** Исправление найденных дефектов: устранение оформляется отдельными задачами.

**Минимум случаев.**
- Исчерпание памяти: вытеснение, затем `OUT_OF_MEMORY`, без падения.
- Исчерпание файловых дескрипторов: отказ соединений, сервер жив.
- Остановка по сигналу с корректным закрытием.
- Разрыв соединения на середине команды.
- Медленный читатель (клиент не читает ответ).
- Большой multi-get при читающем клиенте: ответ передаётся целиком, память ограничена.
- Большой multi-get при остановившемся читателе: память не растёт сверх лимита; при заданном тайм-ауте соединение закрывается.
- Глубокий входной конвейер при остановленной записи: чтение приостанавливается, число незавершённых команд не превышает лимит.
- Повторный перезапуск без утечек прямых буферов.
- 72 часа смешанной работы: память, дескрипторы и потоки без монотонного роста.

**Порог.** Отсутствие падений, утечек и неограниченного роста ресурсов. Допуск роста памяти между стабильными окнами — не более max(5%, 16 МиБ) при одинаковом наборе.

**Критерии приёмки.**
1. Все обязательные сценарии `pass`.
2. 72-часовой прогон подтверждён с сохранением снимков ресурсов по часам.

**Артефакты.** Отчёты, снимки ресурсов, найденные дефекты.

**Роли.** Тестировщик — сильный.

**Ограничения.** Успешный прогон на исправном стенде не заменяет моделирование потери питания там, где оно заявлено.
