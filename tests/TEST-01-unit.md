# TEST-01. Модульные тесты

**Категория.** Модульные.

**Цель.** Проверить корректность отдельных модулей на уровне unit-тестов.

**Метод.** Автономный запуск тестов собственного кода без сети и без внешних сервисов.

**Зависит от.** T-001…T-013.
**Входы.** docs/06, docs/03.
**Результаты.** Отчёт тестов, покрытие, список исключений с обоснованием.
**Вне области.** Исправление найденных дефектов: их устранение оформляется отдельными задачами.

**Минимум случаев.**
- Конфигурация: приоритет источников, разбор размеров, ошибки.
- Часы: детерминированное истечение срока.
- Счётчики: параллельный инкремент и снимок.
- Распределитель: классы размеров, освобождение, отсутствие утечек буферов.
- Хеш-таблица: коллизии, расширение, жизненный цикл.
- Срок жизни: ленивая и активная очистка.
- LRU: порядок вытеснения и счётчики.
- Версии и `cas`: совпадение и несовпадение.
- Декодер и возобновляемый кодировщик: границы, продолжение после backpressure.
- Ёмкости приёмника 0, 1, 2 и `protocol.maxChunkBytes` 1/2: при 0 — `IN_PROGRESS` без записи; при 1 разрешён один обычный байт, но не половина `\r\n`; без активного ожидания; постоянная ёмкость 1 и `maxChunkBytes < 2` отвергаются; при 2 терминатор передаётся целиком (ADR-015).
- Восстановимый отказ ёмкости при `touch`/`getAndTouch`: проверяемое `CacheCapacityException`, старая запись/срок/`cas` не меняются, удержания освобождены, отображение в `SERVER_ERROR out of memory storing object` (ADR-013).
- `gat`/`gats` с ключом `noreply`: лексема разбирается как обычный ключ, команда всегда отвечает, подавление `noreply` не применяется.
- Неизменяемая версия: `set`, `incr`, `append`, `touch` публикуют новую версию; удерживаемое чтение не видит смеси байтов и метаданных; старая версия освобождается после нуля удержаний (ADR-013).
- Два независимых `ResponseWriter` читают одно и то же значение с разными ёмкостями приёмника и поочерёдными продолжениями: оба получают полное значение без порчи и без общего курсора.
- Архитектурный тест: правила зависимостей пакетов по ADR-014 (`Item`/`ItemLease` в `storage`, `GetResult`/`CacheCapacityException` в `engine`, `util` только для реальных потребителей, `stats` только на JDK, прямое `protocol → storage`, отсутствие обратных рёбер).

**Критерии приёмки.**

Дополнительный обязательный профиль [ADR-016](../docs/adr/ADR-016-bounded-command-snapshots.md) (ACCEPTED координатором совместно с ADR-013/015 после ревью `97c8c23b86be`; DESIGN R-04/R-05/R-08/R-09 закрыты, R-07 уже закрыт; результаты этих тестов пока NOT_RUN, не PASS):

- `get A B A missing B`: результат A/B один раз в порядке первого появления, pin каждой уникальной версии один, плата метаданных за все 5 позиций `512 + 512 * 5`; missing фиксирован. Один снимок на команду, не последовательные `get`.
- Снимок при Clock=t: запись с expiry=t исключена, expiry=t+1 включена; после перевода Clock за срок включённая версия выдаётся целиком. Все проверки и относительный TTL multi-gat используют один capturedClock, не время каждого ключа.
- Допуск: сумма активных плат ровно на потолке принимается, превышение на один слот отвергается; checked overflow умножения/сложения, ceiling floor для малых memory.limit. Отказ до захвата и первого байта выдаёт ровно известный SERVER_ERROR, без VALUE/END, refs и резервы возвращаются к исходным.
- Multi-gat с тремя уникальными ключами и дублями: инъекция отказа на каждом резерве/подготовке/передаче владения до публикации; ни один исходный value/TTL/CAS не изменён, неопубликованные блоки и метаданные освобождены. Успех меняет каждый уникальный ключ один раз; публикация больше не выделяет память.
- Завершение, отмена до первого VALUE, отмена посреди значения, disconnect, shutdown и повторные close: все refs и метаданные освобождены ровно один раз, включая невыданные ключи. Два снимка одной версии: закрытие первого не освобождает блок второго; refs0 освобождает retired-блок.
- Native pages/live/retained/reserved accounting при удалении, замене, expiry и eviction; резерв замены либо укладывается в memory.limit, либо OOM без частичной замены. Буфер транспорта после закрытия снимка не читает освобождённый native-блок.
- F1: до allocation/bodyread ровно один атомарный резерв payload+32 и byte[] точной длины, счётчик growth/copy-old-new равен нулю. При memory.limit=256 MiB/item.maxSize=128 MiB допустимое тело100 MiB (>64 MiB) принимается одно в пустой body pool. Checked long overflow/array length и отказ каждого allocation/cancel возвращают полученные резервы, без утверждения о произвольном JVM OOME.
- F1: частичные отправители исчерпали body pool; новый valid storage немедленно выбирает OOM, не ждёт с частичным резервом, читает/отбрасывает ровно payload+CRLF своей scratch lane. Тело содержит `version\r\n` и не исполняется; следующая реальная pipeline-команда version исполняется после framed error, proper noreply подавляет только разрешённую ошибку. Неверный terminator закрывает невосстановимый поток; oversized discard не создаёт body array. Тайм-ауты неизменны.
- F2: до регистрации каждой сессии резерв обеих собственных lane по544, lazy allocation; отказ второй allocation/отмена возвращает обе платы и не регистрирует сессию. Nonreaders исчерпали burst: здоровая сессия выдаёт version/OOM/stats через свою transmit512, без ожидания чужого пула; normal replies не имеют отдельной зависимой от burst ветки. При memory.limit=1 и maxChunk=2 CRLF передаётся целиком, хотя snapshot admission может отказать; maxChunk=1 всё ещё отвергается. Fair RR с конечным бюджетом без spin/unlimited callbacks, собственная заполненная lane даёт локальное backpressure, не поздний SERVER_ERROR.
- F3: ровно шесть массивов ёмкостей N/N/N/N/N/250N, ключ250 и unsigned keyLengths; headers 6*64=384, wrapper/cursor/scratch≤128, payload271N≤512N, reference≤8. Проверить фактические layout assumptions целевой HotSpot JDK25 и checked lengths, не заявлять RSS по формуле. Нет perkey объектов/hash table/роста/рекурсии/массива по общему числу сегментов; heapsort и compaction in-place. Внутренний захват не вызывает defensive Item.key(), публичные копии учтены отдельно.
- Все receive/discard/transmit/body/burst, временное форматирование stats/ключей/чисел и копии строки имеют ограниченный учёт до allocation. Проверить точные границы/конкурентный reserve/release всех error/cancel/disconnect/shutdown путей, отсутствие eager itemMax на соединение, сохранность четырнадцати defaults. CRLF ADR-015 сохранён.

Потолки: snapshot `min(floor(memory.limit/16),16 MiB)`, body `max(item.maxSize+32,min(memory.limit,64 MiB))`, control `544*2*connections.max`, optional burst `min(memory.limit,64 MiB)`; native cache отдельно. Проверять логические счётчики отдельно от измеренных heap/native/RSS/p99, не выдавать плату512 за измерение Java-объекта. Locks sorted segments → allocator → LRU; eviction preflight вне набора исключает целевые ключи, повторный захват обновляет Clock, без I/O/queue waits под locks; cursor/close confinement проверяется отменой через event loop.

1. Все обязательные модульные тесты `pass`.

M1: charge `2L*L+256` для int L, perconn `satMul(I,charge)`, global `satMul(C,perconn)`; L/I/C на максимально допустимых значениях не вызывают startup config rejection/урезание public limits. Проверить точное произведение до границы и LIMIT saturation Long.MAX_VALUE выше неё; actual charge/counters не saturate. CAS reserve `charge<=limit-used`: ровно оставшаяся ёмкость принимается, недостаток около Long.MAX_VALUE даёт resource admission failure без overflow/startup error. Ни perconn, ни global theoretical ceiling не выделяется eager.

M2: `get ` плюс 4093 однобайтовых одинаковых ключа через пробел при L8192 (8189 байт до CRLF, 8191 с CRLF): size()==4093, visitor получает все позиции линейно, snapshot выводит один ключ в прежнем порядке. Ноль per-token arrays/views/List/start-offset arrays/getKey byte[]; один raw backing/примитивный parser cursor/KeySequence wrapper, no recursion/O(N²). Каждый геометрический рост до L имеет old+new payload≤2L, headers2*64 и wrapper/cursor≤128 внутри overhead256; final backing не shrink-copy. Проверить immutable borrowed backing до command release, запрет удержания после release, повторные последовательные passes и API всех команд с 0/1/N ключами. Сначала count N, затем snapshot reserve, только затем шесть allocations и flat fill; отказ reserve не создаёт массивов, пик обеих плат до handoff/release виден. Test-only List adapter вне production budget не нужен production API. Full pipeline/control и release/cancel правила прежние, пять heap-пулов отдельно от native; actual layout/RSS не считаются доказанными заданием.
2. Покрытие собственного некритического кода не ниже 85% ветвей, критического — не ниже 95%.
3. Исключения покрытия обоснованы и не удаляют защитные проверки.
4. Тесты не зависят от сети и внешних сервисов.

**Артефакты.** Отчёт тестов, покрытие, список исключений с обоснованием.

**Роли.** Тестировщик — сильный; не автор проверяемых модулей.

**Ограничения.** Покрытие не заменяет испытания отказов и конкуренции.
