# T-009. Хранилище: распределитель и хеш-таблица

**Цель.** Реализовать хранение записей в памяти: распределитель по классам размеров и хеш-таблицу.

**Зависит от.** T-004, T-005.

**Входы.** docs/03 §4.2–4.3, §6, ЧТЗ-03, [ADR-013](../docs/adr/ADR-013-immutable-published-item-version.md), [ADR-014](../docs/adr/ADR-014-package-dependency-edges.md).

**Результаты.**
- Распределитель по классам размеров со страницами фиксированного размера.
- Хеш-таблица со ссылками на записи и расширением.
- Единый блок записи: заголовок, ключ, значение, выравнивание.
- Учёт памяти, статистика по классам.
- Освобождение с учётом удержаний (`ItemLease`).
- Публикация неизменяемой версии по ADR-013: allocate → publish → retire, освобождение старой версии после нуля удержаний, отдельное изменяемое LRU/refcount, `key()` — защитная копия или ограниченное представление только для чтения.
- Типы `Item`/`ItemLease` в пакете `storage` с согласованными сигнатурами (ADR-014).

**Критерии приёмки.**
1. Ключ сравнивается побайтово; коллизии обрабатываются.
2. Размер блока сравнивается с `item.maxSize`.
3. Значения хранятся вне кучи Java.
4. Удаление, замена, просрочка и вытеснение не освобождают блок под удержанием.
5. Нет утечек прямых буферов при любых путях ошибок.
6. `OUT_OF_MEMORY` возвращается после попытки вытеснения.
7. Опубликованная версия не изменяется на месте; при отказе выделения новая версия не публикуется, старое значение сохраняется (ADR-013).
8. `Item.key()` не выдаёт изменяемые хранимые байты; LRU и refcount вынесены из неизменяемой версии (ADR-013).
9. По [ADR-016](../docs/adr/ADR-016-bounded-command-snapshots.md) native-страницы и резерв будущих страниц вместе не превышают `memory.limit`; live/retained/retired/reserved-блоки учтены без двойного счёта. Retired остаётся занятым до refs0 даже после удаления/expiry/eviction; нет ожидания сокета ради замены.
10. Резерв замены атомарен и checked; отказ не меняет исходную запись. Batch-подготовка multi-gat освобождает все неопубликованные резервы при любом отказе и не вытесняет исходный защищаемый набор. Уникальная версия удерживается один раз на снимок, разные снимки имеют отдельные refs; закрытие идемпотентно.

ADR-013/015/016 ACCEPTED координатором после ревью `97c8c23b86be`; R-04/R-05/R-08/R-09 закрыты как DESIGN findings, R-07 уже закрыт. Разрешена реализация интерфейсов T-004; это не закрытие T-009 или PASS реализации/тестов/производительности/релиза. Heap-буферы и метаданные имеют отдельные бюджеты ADR-016 §5, RSS измеряется отдельно.

Уточнение F1/F2/F3: sorted segments → allocator mutex → LRU metadata; allocator под набором не получает новых segment locks и не инициирует eviction. Eviction preflight отдельно после unlock с исключением целевых ключей, затем повторный полный захват/Clock/проверка. Внутренний снимок читает bounded borrowed key view до pin под lock, не создаёт временные Item.key() copies. Проверить возврат всех резервов при cancel/конкретном allocation failure, не обещая восстановление после произвольного JVM OOME. Шесть массивов снимка и отдельные body/control/burst-пулы заданы ADR-016 §5; actual heap/native/RSS и p99 измеряются прототипом, не выводятся из логических плат.

**Проверка задачи.** Unit-тесты распределителя и хеш-таблицы, локальный прогон на утечки. **Трассировка к релизу.** [TEST-01](../tests/TEST-01-unit.md), [TEST-09](../tests/TEST-09-fault-longrun.md).

**Роли.** Исполнитель — сильный; контролёр — сильный.

Полный roster ADR-016: native и пять heap-пулов snapshot/body/control/burst/line. Line charge `2L*L+256`, perconn `satMul(maxInflight,charge)`, global `satMul(connections.max,perconn)`; только LIMIT насыщаются до Long.MAX_VALUE без config rejection/урезания пределов, actual reserve `charge<=limit-used` без насыщения counters. Engine.KeySequence даёт sequential borrowed backing/offset/length, snapshot count N до reserve/allocation массивов и sequential fill без per-token arrays/views/List. Пик line+snapshot учитывается до release slot, нет внутренних defensive Item.key() copies; raw line old+new≤2L плюс overhead256, никаких theoretical-ceiling allocation/RSS PASS.

**Вне области.** Срок жизни, вытеснение, протокол.

**Ограничения.** Не добавлять отдельный буфер под значение. Целостность при конкурентном освобождении обязательна.
