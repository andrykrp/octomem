## Критерии

1. Независимо зафиксирован эталон до правок Java-кода: обычные команды, ошибочные запросы, ответы, состояние до/после, параметры процесса, SHA-256 бинарников/инструмента/источников. Не нормализовать различия значений, исчезновение ключа или CAS-связи.
2. `gets → touch → gets → cas` без конкурентной записи, истечения срока и вытеснения сохраняет токен и принимает CAS; то же для `gat/gats`. Проверить 0/положительный относительный/будущий абсолютный TTL. Отрицательный/прошедший TTL — отдельная ветка: успешный touch, затем miss и CAS NOT_FOUND; gat/gats может вернуть уже захваченное значение/CAS один раз, последующее чтение — miss. Проверить промах и изменение данных конкурентом. Сравнивать отношения токенов внутри процесса, не конкретные числа между серверами.
3. Ранний отказ выделения записи SET по размеру или native-ёмкости инвалидирует ключ. Другие storage-команды не получают это правило автоматически. Для invalid header, bad body, входного admission, позднего body allocation/disconnect и конкурентного SET отдельно записать фазовый оракул; не разрешать позднему callback удалять новый объект по старой ссылке.
4. Удержанный до инвалидации читатель получает согласованную старую версию; новый читатель не видит инвалидированную запись. Освобождение ровно после последнего удержания, без утечки и double free.
5. Полные строки ошибок соответствуют причине, фазе и операции: арифметический EOM, начальный storage OOM, NOT_STORED при отказе объединённого append/prepend, неправильная дельта, неправильный exptime (включая знаковые 32-битные wire-границы). Валидный `noreply` подавляет ответ, не отменяет семантику; последующий `version/get` показывает правильную границу потока. Gat/gats всегда отвечают.
6. Независимые регрессии сначала демонстрируют расхождение там, где оно действительно есть; уже совместимый код не менять ради видимости работы. После исправления — целевые тесты, полный verify/coverage по действующим порогам, дифференциальные тесты и свежий review. Ноль required skips; NOT_RUN не повышается до PASS.
7. Документированы все неустранённые различия; full Memcached replacement, производительность и регистрация не объявляются доказанными. Нужен новый кандидат и повторение затронутых приёмочных проверок, не переписывание frozen-отчётов.

**Вне области:** binary/meta/UDP/TLS/SASL, новые конфигурационные defaults, Redis, GUI, релиз/деплой/коммит, юридические заверения. Эти направления не отменены, но не маскируются под небольшую правку classic text.

**Артефакты:** план независимого оракула, raw-транскрипты, source/artifact identities, тестовые отчёты с точными числами, review и список остаточных рисков. На момент создания карточки ни один исполняемый критерий не проверен.
