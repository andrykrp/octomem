# OPS-05. Разбор инцидентов

**Цель.** Определить порядок действий при сбоях и деградации сервиса кеша.

**Зависит от.** OPS-02, OPS-03.

**Входы.** [docs/07 §5, §7](../docs/07-security-operations-release.md), OPS-02, OPS-03.

**Результаты.**
- Перечень типовых инцидентов: недоступность, рост вытеснений, отказы соединений, ошибки памяти, отказ процесса.
- Действия первой очереди для каждого типа.
- Что фиксировать для последующего разбора без утечки данных.
- Правила эскалации и когда требуется человек.

**Критерии приёмки.**
1. Для каждого типа инцидента есть проверяемые признаки и первые действия.
2. Сбор диагностики не включает ключи и значения кеша.
3. Разбор не приводит к потере доказательств.
4. Действия, изменяющие продуктивную среду, помечены как требующие человека.

**Проверка.** Учебный разбор на стенде, проверка наличия признаков и сбора диагностики.

**Роли.** Исполнитель — дешёвый; контролёр — сильный.

**Вне области.** Инциденты основной базы и сети заказчика.

**Ограничения.** Секреты и персональные данные не покидают стенд без решения человека.

**Бюджет.** Оценивается координатором по объёму и доступным проверкам; локального манифеста процесса нет.
